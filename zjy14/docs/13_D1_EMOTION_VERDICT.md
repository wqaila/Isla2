# D1 情绪验证报告

> 日期：2026-11-16
> 决策点：D1「CosyVoice3 的情绪指令是否真的能表达情绪」
> 结论：**未通过**。情绪指令在本模型上无效，建议走路线乙（降级）

---

## 一、结论

**CosyVoice3-0.5B 的情绪指令无法产生可测量的情绪差异。**

三条独立证据：

| 验证路径 | 真指令差异 | 安慰剂效应 | 判定 |
|---|---|---|---|
| 混合模式（组合 prompt） | 10.1 Hz | **15.4 Hz** | ❌ 未超过安慰剂 |
| 官方 `instruct2`（空 spk） | 24.3 Hz | **72.5 Hz** | ❌ 未超过安慰剂 |
| 方向性检查 | 开心 −5.3 / 伤心 −15.4 | 同向 | ❌ 不符合情绪直觉 |

**关键判据**：加入「请用蓝色的语气说一句话」这种**无意义指令**，产生的 F0 变化（15.4 / 72.5 Hz）比真正的情绪指令（10.1 / 24.3 Hz）还大。

这说明模型对 `prompt_text` 的反应只是"文本变长了"，而不是"理解了情绪"。

---

## 二、验证方法

### 2.1 为什么用安慰剂对照

第一轮测试（`_d1_final.py`）显示 5 种情绪的 F0 全部**低于**基线（−10 到 −32Hz），
且 4/5 有"显著差异"。看起来像指令生效了。

但有个疑点：如果是指令生效，happy 应该**升调**、sad 应该**降调**，方向应该相反。
全部同向下降，更像是系统性偏移。

于是设计安慰剂对照：

| 组 | prompt 内容 | 作用 |
|---|---|---|
| 基线 | 参考文本 | 无指令 |
| **安慰剂** | 「请用**蓝色**的语气说一句话」+ 参考文本 | 无情绪含义的指令 |
| 开心 | 「请非常开心地说一句话」+ 参考文本 | 真指令 |
| 伤心 | 「请非常伤心地说一句话」+ 参考文本 | 真指令 |

**判据**：若「开心 vs 伤心」的差异 > 「安慰剂 vs 基线」的 2 倍，才算指令有效。

### 2.2 采样设计

- 混合模式：每组 5 次采样，取中位数
- 官方路径：每组 3 次采样（每次需重编码参考音频，较慢）
- 同一合成文本（29 字）、同一参考音频

### 2.3 技术方案修正（重要）

验证过程中发现此前 Phase 0 的混合调用方案有缺陷：

| 方案 | 时长 | 语速 | 说明 |
|---|---|---|---|
| 正常 `zero_shot` | 5.76s | 6.17 字/秒 | 基准 |
| prompt=参考文本 + **保留** llm token | 6.16s | 6.11 字/秒 | ✅ 正常 |
| prompt=参考文本 + **删除** llm token | 14.72s | 2.25 字/秒 | ❌ 慢 2.5 倍 |
| prompt=指令 + **删除** llm token | 14.64s | 3.53 字/秒 | ❌ 慢 |

**根因**：删掉 `llm_prompt_speech_token` 会让 LLM 缺少语音前缀约束，倾向于生成冗长内容。

Phase 0 当时为了避免卷积报错而删除该 token，代价是生成速度恶化 2.5 倍——
这个副作用当时没被发现，因为只看了单次合成的音色指标，没看时长。

**改进方案（W2）**：prompt 构造成「指令 + `<|endofprompt|>` + 参考正文」，
同时**保留** `llm_prompt_speech_token`：

```
prompt_text = "You are a helpful assistant. 请非常开心地说一句话。<|endofprompt|><参考正文>"
```

实测 6.72s / 5.66 字/秒，接近基线，且不报错。**这个方案应作为后续实现基础。**

## 三、详细数据

### 3.1 混合模式（W2 组合 prompt，5 次采样）

| 方案 | F0 中位 | F0 标准差 | 起伏中位 | 时长中位 |
|---|---|---|---|---|
| 基线 | **358.2** | 7.1 | 0.181 | 6.04s |
| 安慰剂（蓝色） | 342.9 | 20.3 | 0.180 | 6.36s |
| 开心 | 352.9 | 17.8 | 0.184 | 6.76s |
| 伤心 | 342.9 | 15.8 | 0.186 | 6.44s |

- 开心 vs 伤心：**10.1 Hz**
- 安慰剂 vs 基线：**15.4 Hz** ← 更大
- 组内噪声：20.3 Hz

**10.1 < 15.4 < 20.3，真指令差异既小于安慰剂效应，也小于组内噪声。**

### 3.2 官方 instruct2 路径（3 次采样）

| 方案 | F0 中位 | F0 标准差 | 起伏中位 | 时长中位 |
|---|---|---|---|---|
| 基线 | **358.2** | 2.5 | 0.181 | 6.12s |
| 安慰剂 | 285.7 | 26.0 | 0.209 | 10.68s |
| 开心 | 324.3 | 22.4 | 0.211 | 13.00s |
| 伤心 | 300.0 | 12.8 | 0.162 | 10.12s |

- 开心 vs 伤心：**24.3 Hz**
- 安慰剂 vs 基线：**72.5 Hz** ← 大 3 倍
- 组内噪声：26.0 Hz

**官方路径的安慰剂效应更夸张（72.5Hz），且时长从 6.12s 恶化到 13.00s。**

### 3.3 第一轮 6 情绪测试（已被推翻的初判）

`_d1_final.py` 的结果曾显示 4/5 情绪"有显著差异"：

| 情绪 | F0 差 | 显著项 |
|---|---|---|
| happy | −24.9 | F0 |
| sad | −10.4 | 节奏 |
| angry | −31.7 | F0 |
| comforting | −10.4 | 无 |
| playful | −24.9 | F0 |

**这个结论是错的**，因为没做安慰剂对照。全部同向下降正是"prompt 变长"的表现。

保留此数据作为反面教材：**没有对照组的 A/B 测试会得出错误结论。**

## 四、对项目的影响

### 4.1 D1 决策：走路线乙

原决策 D1 有两个分支：

| 路线 | 内容 | 结论 |
|---|---|---|
| 甲 | 多情绪表达（6 种情绪） | ❌ **不可行** |
| 乙 | 降级为语速/音量/停顿控制 | ✅ **采用** |

**路线乙的具体做法**：

1. **保留确定生效的控制维度**：
   - `speed` 语速（已验证：0.9/1.0/1.1 有明确时长差异）
   - 音量（可通过音频层增益实现，不依赖模型）
   - 停顿（可通过文本标点/分句控制）

2. **情绪交由 LLM 侧用词表达**：
   - zjy13 的角色卡已有 `emotional_expression` 字段
   - 让 LLM 在文本层面体现情绪（"嘿嘿~" vs "唔…"），TTS 只负责忠实朗读
   - 这与原提示词"不让每句话的情绪标签导致声音身份漂移"的要求一致

3. **文档如实标注**：模型不支持独立情绪控制

### 4.2 需要修改的既有设计

| 位置 | 现状 | 应改为 |
|---|---|---|
| 决策 D4 | 3 官方 + 2 实验情绪 | 情绪标签保留为元数据，但不映射到模型指令 |
| `SynthesisRequest.emotion` | 接受但未生效 | 明确标注"仅记录，不影响合成" |
| 角色卡的 `allowed_emotions` | 6 种 | 保留，但语义改为"允许 LLM 表达的情绪" |
| Phase 2b 计划 | 情绪映射 + 平滑状态机 | 改为语速/停顿控制 + LLM 侧情绪 |

### 4.3 不影响的部分

- 音色克隆（相似度 0.9208）✅
- 文本前端 TN ✅
- 采样稳定性（CV 0.028）✅
- 角色/声音管理 ✅

**Phase 2a 的成果全部有效。**

## 七、教训

1. **没有安慰剂对照的 A/B 测试会骗人**。第一轮"4/5 情绪有差异"完全是假象。
2. **方向性检查很重要**。开心和伤心同向变化，本身就说明不对。
3. **副作用要主动查**。Phase 0 为了绕开报错删掉 llm token，代价是速度慢 2.5 倍，当时没发现。
4. **客观指标只能证伪，不能证真**。指标有差异不等于情绪被表达；指标没差异则基本可以确定无效。

## 一、先回答你的问题：modelscope token 有什么好处

### 它解决什么

`wetext` 的初始化代码（`wetext/wetext.py:38`）：

```python
if tagger_path is None or verbalizer_path is None:
    repo_dir = snapshot_download("pengzhendong/wetext")   # ← 这里要联网下载
```

**它要下载 4 个 `.fst` 文件**（中英文各一套 tagger/verbalizer），约几十 MB。
没有 token 时 modelscope 返回 403，初始化失败，`text_frontend` 降级为空。

### 有 token 之后能做什么

**文本正则化（TN）**：把书面写法转成口语读法。

| 输入 | 无 TN（当前） | 有 TN |
|---|---|---|
| `2026年11月9日` | 可能读成"二零二六…"或跳过 | "二零二六年十一月九日" |
| `25度` | 数字直读 | "二十五度" |
| `3.14` | 可能读"三点一四"或错 | "三点一四" |
| `100%` | 符号可能被忽略 | "百分之一百" |
| `AI` | 可能逐字母 | "人工智能"或"诶艾" |
| 空格、括号、破折号 | 原样送进模型 | 规范化处理 |

**这对"像不像机器人"有影响，但不是我这次发现的三个主因之一。** 影响的是：
- 数字/符号多的文本会读错或读得生硬
- 停顿与标点处理更自然

**结论**：token 值得配，但**优先级低于下面三个修复**。配了是锦上添花，不配也不会是"像机器人"的主因。

### 怎么配（免费）

1. 注册 <https://www.modelscope.cn>（免费）
2. 个人中心 → 访问令牌 → 新建
3. `modelscope login --token <你的token>` 或设环境变量 `MODELSCOPE_API_TOKEN`
4. 验证：`python -c "from wetext import Normalizer; Normalizer()"` 不报错即可

**替代方案**（如果不想注册）：把 4 个 fst 文件手动下载放到本地，然后传 `tagger_path` / `verbalizer_path` 参数。我可以帮你写这个补丁。

## 二、找到的三个真根因

### 根因 1：参考音频含 22–34% 纯数字零静音（最重要）

这是本次诊断最关键的发现。

| 候选 | 原始时长 | 纯零静音 | 裁后时长 | 平坦度变化 | HNR 变化 |
|---|---|---|---|---|---|
| 1.0 | 9.38s | **34.19%** | 6.06s | 0.4044 → **0.2685** | 2.6 → **6.6dB** |
| 1.4 | 7.71s | **31.17%** | 5.44s | 0.4385 → **0.2794** | −1.3 → **4.2dB** |
| 1.5 | 9.59s | **22.13%** | 7.38s | 0.3793 → **0.2840** | 3.2 → **5.2dB** |
| 1.6 | 9.01s | **30.89%** | 6.49s | 0.3490 → **0.2465** | 5.1 → **7.6dB** |

**解读**：
- 纯零静音 = 噪声门处理的痕迹，真实录音不可能有绝对零
- 这些静音被模型当成"参考音频的一部分"去学习，导致模型以为说话就该这样断
- 裁掉后 HNR 提升 2–5.5dB，平坦度下降 0.09–0.16 —— 这两项都直接对应"人声自然度"

**1.6 裁后 HNR 7.6dB、平坦度 0.2465，已经非常接近官方示例（6.0dB / 0.2150）。**

### 根因 2：合成文本远短于参考文本（官方明确警告）

`cosyvoice/cli/cosyvoice.py:94-95`：

```python
if (not isinstance(i, Generator)) and len(i) < 0.5 * len(prompt_text):
    logging.warning('synthesis text {} too short than prompt text {}, this may lead to bad performance')
```

我们的实际情况：

```
参考文本 85 字符（"我一直都在努力维持优雅美丽可爱…"）
合成文本 18 字符（"今天天气真不错，我们一起出去走走吧。"）
比值 0.21  <<  0.5 阈值  → 必然触发警告
```

**实测影响**（同一参考，只改文本长度）：

| 场景 | 文本长度比 | 平坦度 | HNR | 质心 |
|---|---|---|---|---|
| 参考本身 | — | 0.2760 | 6.7dB | 2913Hz |
| **长文本** | **1.08** | **0.2796** | **6.3dB** | **3064Hz** |
| 短文本 | 0.21 | 0.3090 | 5.1dB | 3403Hz |

**长文本几乎完美还原参考（平坦度 0.2796 vs 0.2760，HNR 6.3 vs 6.7）**，短文本则全面劣化。

这解释了为什么"复述参考原句"时音色几乎完美（Phase 0 已测，质心差仅 −56Hz）。

### 根因 3：候选短片的 HNR 普遍偏低

| 候选 | 原始 HNR | 裁后 HNR | 判断 |
|---|---|---|---|
| 1.0 | 2.6dB | 6.6dB | 裁后可用 |
| 1.4 | **−1.3dB** | 4.2dB | 原始很差，裁后勉强 |
| 1.5 | 3.2dB | 5.2dB | 裁后较好 |
| 1.6 | **5.1dB** | **7.6dB** | **最好** |
| 官方示例 | 6.0dB | — | 基准 |

HNR（谐噪比）低意味着气声/噪声成分高，克隆出来会"沙哑"或"机械"。

**1.6 是原始质量最好的**（5.1dB），裁后 7.6dB 甚至超过官方示例。

## 三、修复方案

### P0-1：裁掉参考音频首尾静音（立刻可做）

**做法**：导入参考音频时自动裁剪，而不是原样使用。

已实现的原型在 `probe/_trim_test.py` 的 `trim_silence()`：
```python
def trim_silence(x, sr, rel_thr=0.02, pad_s=0.05):
    """裁掉首尾静音，保留 50ms 余量。"""
```

**建议**：把这个逻辑加进 `custom_voice/speaker/validate.py`，作为导入流程的一部分，并把裁剪后的音频存为新文件（**不覆盖原始素材**）。

### P0-2：参考音频选 1.6.mp3（"晚上好，如此美妙的夜晚"）

综合客观指标：

| 候选 | 裁后 HNR | 裁后平坦度 | F0 | 推荐度 |
|---|---|---|---|---|
| **1.6** | **7.6dB** | **0.2465** | 316Hz | ⭐⭐⭐ 最佳 |
| 1.0 | 6.6dB | 0.2685 | 340Hz | ⭐⭐ |
| 1.5 | 5.2dB | 0.2840 | 304Hz | ⭐⭐ |
| 1.4 | 4.2dB | 0.2794 | 253Hz | ⭐ |

**1.6 的 F0 316Hz 也最接近素材中位 317Hz**，三项指标全部最优。

**但最终要你听**——客观指标能筛掉差的，但"像不像角色"要耳朵判断。

### P0-3：控制文本长度比 > 0.5

**这是引擎层的硬约束，必须在代码里处理**，不能靠调用方自觉。

方案：
```python
# custom_voice/inference/engine.py（Phase 2 实现）
MIN_TEXT_RATIO = 0.5

def _check_text_ratio(self, text: str, prompt_text: str) -> None:
    ratio = len(text) / len(prompt_text)
    if ratio < MIN_TEXT_RATIO:
        logger.warning(
            "合成文本过短，音色可能失真",
            extra={"extra_fields": {
                "text_len": len(text),
                "prompt_len": len(prompt_text),
                "ratio": round(ratio, 2),
                "threshold": MIN_TEXT_RATIO,
            }},
        )
```

**但更重要的是理解其含义**：
- 参考文本 85 字符对应 9.7s 音频
- 如果合成文本只有 18 字符（约 2s 音频），模型"参考"的韵律远长于要生成的
- 官方建议比值 ≥ 0.5，即合成文本至少 43 字符（约 5s 音频）

**实践建议**：
1. 参考音频的文本控制在 **30–50 字符**（对应 4–6 秒音频），而不是 85 字符
2. 或对短文本做"上下文补足"——把上一句一起送去合成，再截取需要的部分（复杂，不建议第一版做）

### P1：启用文本前端（需要 modelscope token）

见第一节。影响数字/符号读法，非主因。

### P1：改进选段策略

`prepare_voice_ref.py` 当前打分 = 信噪比 60% + 时长 40%，建议改为：

```
音色自然度（HNR）     40%   ← 新增，直接对应"像不像人声"
静音比例（越低越好）   25%   ← 新增，噪声门痕迹惩罚
时长贴近理想值        20%
信噪比                15%
```

并增加硬性门槛：
- 纯零静音比例 > 15% → 警告
- HNR < 3dB → 拒绝

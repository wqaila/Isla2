## 二、交付成果

### 2.1 一句话

> 以前让板子说话要开 2~3 个终端、顺序错了网关直接退出；
> 现在**双击一个 `.bat`**，网页上点「一键启动全部」即可。

### 2.2 三个入口，同一套 API

| 入口 | 地址 | 需要 node | 需要 zjy14 后端 | 适用 |
|---|---|:-:|:-:|---|
| **网页一键启动** | `http://127.0.0.1:5173/services` | ✅ | ❌ | 日常使用（信息最全） |
| **独立控制台** | `http://127.0.0.1:50100/` | ❌ | ❌ | 兜底（自包含单文件 HTML） |
| **手工启动** | 命令行 | ❌ | — | 排查 |

**关键设计**：编排逻辑只存在于 `launcher/orchestrator.py` **一处**，
两个前端只负责展示。不存在两套启动逻辑。

**为什么能冷启动**：网页是静态前端（Vite），启动器是独立进程（:50100），
两者都**不依赖** zjy14 后端 :50001 —— 所以 TTS 还没起来时页面照样能打开。

### 2.4 TTS 归属是怎么钉死的（需求重点）

启动网关时**显式注入**环境变量：

```python
env["TTS_BASE_URL"]    = "http://127.0.0.1:50001"
env["ASR_SERVICE_URL"] = "http://127.0.0.1:50002"
```

**为什么这能生效**：zjy13 的 `load_env_file()` 用的是
`load_dotenv(override=False)` —— **进程环境变量优先于 `.env`**。
所以即使 `zjy13/.env` 里写着 `TTS_BASE_URL=:50000`，网关仍会走 :50001。

**实证**（不是推断）：跑完一轮对话后查 zjy14 的合成历史，
出现了与那一轮音频吻合的记录：

```
engine=cosyvoice3   voice_id=elysia   duration_s=9.0
total_ms=7813.6     first_audio_ms=1597.6   rtf=0.8682
```

### 2.5 ASR 独立化（新增能力）

改造前 ASR 内嵌在网关：网关启动时才 `ASREngine().load()`。
现在新增 `zjy13/server/asr_service.py`（:50002），网关用 `--asr-url` 转过去，
**配置后不再本地加载 FunASR**。

| 收益 | 说明 |
|---|---|
| 显存不重复 | 同一份模型只驻留一次 |
| 可独立重启 | ASR 崩了不用断板子连接 |
| 可独立验证 | `POST :50002/transcribe` 直接测识别 |

**为什么用标准库而非 FastAPI**：`.venv-asr` 里没有 fastapi/uvicorn
（实测 `find_spec` 均为 False），装它们纯增依赖面。

### 2.6 编排规则

| 服务 | 依赖 | 必需 | 就绪判据 |
|---|---|:-:|---|
| `tts` | — | ✅ | `:50001/health` 返回 200 且 `ok=true` |
| `asr` | — | ✅ | `:50002/health` 且 `loaded=true` |
| `llm` | — | ❌ | `.env` 关键字段齐全（代理不通只警告） |
| `gateway` | tts, asr | ✅ | `:8765/api/devices/health` |

设计要点：

1. **失败不连坐**：`tts` 失败只让 `gateway` 变 `blocked`；
   `llm` 探测照常执行（它是无副作用的只读检查）。
   早期实现用全局 `failed` 短路，会把 LLM 也标成 `skipped` —— 已修。
2. **`required=False` 不参与总判定**：LLM 是云端，代理没开不该判「整条链路不可用」。
3. **快速失败**：启动后 6 秒内进程退出且端口未监听 → 立刻把日志尾巴回给前端，
   而不是让用户干等 `ready_timeout`（TTS 是 180 秒）。

## 四、修复的缺陷（今日共 18 项）

> 这一节是本日最有价值的部分：**每一个都是实测踩到、定位到根因、再修掉的**。

### 4.1 静默失效类（最危险：没有报错，只是不工作）

#### ① 控制台页面 JS 语法错误 → 所有按钮点不动

用户反馈「点击一键启动没有用」。后端一直是好的（`POST /api/start-all` 实测
1.19 s 返回 `ok=True`），问题在页面：

```js
document.addEventListener("click", (e) => {      // 这个函数不是 async
  const d = await getJSON(`/api/log/${name}`);   // ← SyntaxError
});
```

浏览器**解析整段脚本失败** → 一个事件处理器都没注册 →
页面照常打开、按钮全部静默失效、**屏幕上没有任何提示**。
`node --check` 一跑就报 `SyntaxError: await is only valid in async functions`。

**修法**：抽成 `async function loadLog()`；并把页面拆成
**「引导脚本 + 主脚本」两段** —— 引导脚本先装 `window.onerror`，
1 秒后检查 `window.__consoleReady`，主脚本挂了就在顶部亮红条。

#### ② `.ps1` 缺 UTF-8 BOM → 整段脚本一行都不执行

PowerShell 5.1 读 `.ps1`：**有 BOM 按 UTF-8**，**无 BOM 按 ANSI(GBK)**。
含中文注释的无 BOM 文件会被按 GBK 误解，字节序列凑出多余括号：

```
Unexpected token '}' in expression or statement.
Missing closing '}' in statement block or type definition.
```

新写的 3 个 `.ps1` 全部踩中。值得一提：项目**原有的** `start.ps1`
本来就是 UTF-8+BOM —— 说明前人踩过并绕开了，只是没文档化。

#### ③ 双击 `.bat` 乱码 → 注释正文被当命令执行

用户双击 `一键启动网页.bat`，屏幕刷出：

```
'嶅姟鍣ㄣ€嶁啋' 不是内部或外部命令，也不是可运行的程序
'痌' / 'se' / 't' / 'rshell' / '9009' 不是内部或外部命令...
```

文件当时是 **UTF-8 无 BOM + 纯 LF**，双错叠加：

| 问题 | cmd.exe 的行为 |
|---|---|
| 纯 LF | 只认 **CRLF**；纯 LF 把行拆错，`rem` 前缀丢失 → **注释被当命令执行** |
| UTF-8 字节 | 按 **ANSI(cp936)** 解析 → 中文变「嶅姟鍣」 |

#### ④ `.bat` 的 CRLF 被 git 规范化回 LF → clone 后必现

改完文件本机是好的，但索引里存的是纯 LF：

```
$ git show :zjy14/一键启动网页.bat
CRLF=0  纯LF=29
```

**任何人重新 clone 拿到的都是坏的** —— 本机"看着正常"只因工作区还是 CRLF。
根因是 `zjy14/.gitattributes` 里 `* text=auto eol=lf` 一行通吃。
修法是其后追加 `*.bat text eol=crlf`（gitattributes 后匹配者优先）。

> 曾尝试加**根级** `.gitattributes`，它把 zjy2~zjy11 几十个无关文件的行尾
> 一起纳入改动，影响面过大，已撤回，只保留 zjy14 内的定点修复。

### 4.2 误杀与假成功类

#### ⑤ 停止 TTS 误杀 `wslrelay` → 假成功 + 破坏 WSL 转发

用户反馈弹出「已终止占用端口 50001 的进程 [11180]」，但 TTS 其实没停。
查证属实，而且界面给的是**假成功**：

```
TCP 127.0.0.1:50001 LISTENING 11180   ← wslrelay.exe（WSL 端口转发）
WSL 内: python -m custom_voice.server (PID 339, RSS 5.7 GB)  ← 真正在跑
```

旧逻辑在「端口仍被占」时按端口找 PID 再 `taskkill /T /F`。对 WSL 服务三步全错：

| 后果 | 说明 |
|---|---|
| 服务没停 | 杀的是转发进程，uvicorn 继续跑、继续占 5.7 GB 显存 |
| 假成功 | 显示「已终止…」，用户以为停了 |
| 破坏环境 | 打断 WSL localhost 转发，且 WSL 会立刻重新拉起它 |

**修法**：新增 `NEVER_KILL_PROCESS_NAMES`（16 项：`wslrelay`/`wslhost`/`vmmem`/
`lsass`…）；**WSL 服务完全不走按端口杀**，只走 `pkill`；
`pkill` 失败时返回 `ok=False` + `action="stop_failed"` + `needs_manual`，
**不再因为「端口恰好没了」而报成功**。

#### ⑥ `start_web.ps1 -Stop` 用 `taskkill /T` → 连带杀死 ASR/网关

`/T` 会结束进程树，而 ASR/网关正是启动器的子进程 —— 实测 ASR 就这样被带走。
更糟的是脚本紧接着打印「语音链路服务不会被停止」，与事实**相反**。

**修法**：先调 `/api/stop-all` **有序停止**（网关→ASR→TTS），
再不带 `/T` 结束启动器；措辞改为准确描述。

### 4.4 `start_tts.ps1` 为什么要「隐藏 powershell 持有 wsl」

TTS 需要一个**常驻的 `wsl.exe` 会话**，否则 WSL2 在会话结束后关掉 VM，
把里面的 uvicorn 一起带走。实测三种写法都是秒退、日志 0 字节：

| 写法 | 结果 |
|---|---|
| `setsid nohup ... &`（脚本立刻返回） | 秒退（会话结束 → VM 关闭） |
| `Start-Process wsl.exe -WindowStyle Hidden` | 秒退 |
| `Start-Process wsl.exe`（不带 Hidden） | 秒退 |

可行做法：起一个**隐藏的 powershell**，在它里面**前台**跑 `wsl`：

```powershell
Start-Process powershell.exe -WindowStyle Hidden `
  -ArgumentList @("-NoProfile","-Command","wsl.exe -d <distro> -e bash <sh>") `
  -RedirectStandardOutput logs\tts_manual.log -RedirectStandardError logs\tts_manual.err.log
```

实测冷启动 **17 s** 就绪，`engine=cosyvoice3 device=cuda load_s=9.08`。
持有者 PID 记在 `logs\tts_holder.pid`，`stop_tts.ps1` 会一并清理。

## 五、环境限制（诚实记录）

### 5.1 Python 进程树无法访问 WSL —— 已穷举验证

**现象**：从 PowerShell 直接调 `wsl` 正常；从 **Python 子进程**调一律返回
`Wsl/E_ACCESSDENIED`。因此启动器（Python）无法启停 WSL 里的 TTS。

**穷举过的路径（全部被拒）**：

| 尝试 | 结果 |
|---|---|
| `wsl.exe`（stdio：管道 / 文件 / 新控制台 / 继承，四种都试） | `E_ACCESSDENIED` |
| 经 `cmd.exe` 转一层 | 拒绝 |
| 经 `powershell.exe -Command` / `-File` | 拒绝 |
| `ctypes` 直调 `wslapi.dll` 的 `WslLaunch` | 拒绝（`0x80070005`） |
| `schtasks` 建一次性任务跳出进程树 | `schtasks` 自身「找不到路径」 |
| 读注册表 `HKCU\...\Lxss` | ✅ 可读（证明发行版名没错） |

**结论**：限制在**进程令牌**层面，Python 侧无法自救。这是运行环境的限制，
不是代码缺陷。

### 5.2 已给出的解法（不是"绕不过就算了"）

1. `/api/status` 返回 `wsl_available`（探测结果缓存，不拖慢轮询）；
2. 页面顶部：`wsl_available=false` 时**提前**显示提示 + 可复制命令，
   TTS 卡片按钮带 `title` 说明 —— **不再让用户点一次失败一次**；
3. 新增 `scripts/start_tts.ps1` / 强化 `scripts/stop_tts.ps1`（纯 PowerShell）。
   起好后回网页点「刷新状态」即可**接管**（启动器按端口+健康检查判定，
   不要求服务由它自己拉起）—— 已实测接管成功。

### 5.3 其它

| 限制 | 说明 |
|---|---|
| 脚本输出接管道时会等到服务退出 | `Start-Process` 走 `CreateProcess(bInheritHandles=TRUE)`，子进程继承父进程句柄。实测 `.\start_web.ps1 \| Tee-Object` 会等到服务全部退出才返回（398 s）。**日常双击 `.bat` 不受影响**（2.3 s 返回）。无法用纯 PowerShell 绕开（需 WMI/P-Invoke，代价是丢失服务日志）。 |
| 版本台账 §十一 的 `3572 MB` | 全局替换测试数时差点误改，已在脚本里加断言保护 |

## 六、经验教训

### 6.1 「静默失效」是最贵的一类 bug

今天 4 个 P0 里有 3 个是**不报错的失效**：

- 一行 JS 语法错误 → 整页按钮死掉，页面看起来完全正常
- `.ps1` 缺 BOM → 整个脚本一行不执行，调用方只看到莫名报错
- `.bat` 换行错 → 注释被当命令执行，刷屏但没人知道根因

**教训**：前端脚本与 shell 脚本的失效是"静默且彻底"的。
必须有两道兜底：**页面自检**（`__consoleReady` + 错误红条）
和**静态校验**（`node --check`、PowerShell `Parser.ParseFile`）。

### 6.2 「端口没了」≠「服务停了」

停止 TTS 的事故根因就是这个：Windows 上看到的监听者是 `wslrelay`，
杀掉它端口确实"消失"了一瞬，WSL 又立刻重新转发出来。
**判断服务是否真的停止，要看健康检查/进程，不是端口的可达性** ——
中间可能隔着转发层。

### 6.3 只有 BOM/换行是不够的，还要验证到「别人 clone 下来」

`.bat` 改好后本机正常，但 `git show :path` 显示索引里是纯 LF。
**这类问题只能靠真实 clone 验证**，看工作区会得出错误结论。

实测验证方式：

```powershell
git clone --depth 1 file:///D:/xiangmudaima $env:TEMP\chk
# 检查：CRLF>0、纯LF=0、无 BOM、GBK 可解
# 再在该目录里实跑 .bat，确认只有预期中文提示、无乱码命令
```

结果：`CRLF=29 / 纯LF=0 / BOM=False / GBK 可解`，
运行只输出一条 `[错误] 找不到 scripts\start_web.ps1`（故意放空目录），**零乱码命令**。

### 6.4 编码规则两套，且方向相反

| 文件类型 | 编码 | 换行 | 依据 |
|---|---|---|---|
| `.ps1` | UTF-8 **带 BOM** | 任意 | PowerShell 5.1 无 BOM 时按 GBK 解析 |
| `.bat` | **GBK**，无 BOM | **CRLF** | cmd.exe 只认 CRLF，按 ANSI 解析；BOM 会被当命令 |

两套规则都有测试锁着（`test_ps1_has_utf8_bom` / `test_bat_uses_crlf` 等）。

### 6.5 能力不足时不要假装成功

停 TTS 那一版宁可返回 `ok=False` + 一条确定可用的命令，
也不在界面上造「已终止」的假象 —— 那种假象会让人以为服务停了，
而显存还占着 5.7 GB。**假成功比失败更贵**。

### 6.6 错误注释也是 bug

`start_web.ps1` 里我曾写「改用 `-RedirectStandardOutput` 后 2.3 秒返回」，
把两件事混为一谈。实测发现管道场景其实会挂住。已改正为准确描述
（文档 §6.4）。**代码注释里的错误断言会误导后来人，必须当缺陷处理。**

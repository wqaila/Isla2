## 逐条展开

### D1：两手准备（待盲听）

不阻塞开工，但架构必须同时容纳两条路：

**路线甲（情绪有效）**
- `expression/emotion.py` 映射 6 情绪 → 指令模板
- 验收：盲听 6 种情绪至少 4 种可辨认
- 交付情绪 A/B 对照页

**路线乙（情绪无效）**
- 降级为 `speed` / `volume` / `pause` 三个确定生效的维度
- 情绪改由 LLM 侧用词表达（zjy13 角色卡已有 `emotional_expression` 字段）
- 文档如实标注："模型不支持独立情绪控制"

**共同部分（两条路都要做）**
- 混合调用模式（`engine.py`，见方案 3.4）
- 指令解析器（`frontend/instruction.py`）
- 情绪平滑状态机（即使路线乙，也用于语速/停顿的连续变化）

**决策点**：你听完 `_audio_probe/` 后告知结果，我据此锁定 Phase 2 验收口径。
在此之前，Phase 2 按路线甲的接口设计，但实现上把"情绪→指令"做成可替换策略。

### D2：引擎升级（方案 A）

```text
现状（zjy13）：
  ESP32 固件 → zjy13/server/ws/server.py → zjy13/server/tts/client.py
                                        → WSL HTTP :50000 → tts_server_wsl.py → CosyVoice3

升级后：
  ESP32 固件 → zjy13/server/ws/server.py → zjy14 引擎服务
                                        → WSL HTTP :50001 → custom_voice/inference/engine.py
                                                          → CosyVoice3（混合调用）
```

**具体动作**：
- zjy13 侧只改一处：`TTSConfig.base_url` 从 `:50000` 改到 `:50001`
- zjy14 的 HTTP 接口**保持 `/synthesize` 与 `/health` 的请求/响应契约**，zjy13 的 `TTSClient` 无需改动
- 新增字段（emotion / style / instruction）通过可选参数扩展，旧调用不受影响
- 固件、协议、角色卡：**一行不改**

**回滚**：把 `base_url` 改回 `:50000` 即恢复原状。

### D4：3 + 2 情绪

| 情绪 | 指令来源 | 验收级别 |
|---|---|---|
| neutral | 无指令（基线） | 正式 |
| happy | 官方 `请非常开心地说一句话` | 正式 |
| sad | 官方 `请非常伤心地说一句话` | 正式 |
| angry | 官方 `请非常生气地说一句话` | 正式 |
| comforting | **自造** `请用温柔安慰的语气说一句话` | 实验性，标"未验证" |
| playful | **自造** `请用俏皮活泼的语气说一句话` | 实验性，标"未验证" |

自造两条在配置里带 `experimental: true` 标记，UI 上明确区分，不混入正式验收统计。

### D5：先非流式

| 阶段 | 流式状态 |
|---|---|
| Phase 2–3 | 全部非流式 |
| Phase 4 | 实现流式 + 长短句路由（阈值待实测，参考 zjy13 的 18 字分界） |

`engine.py` 接口从一开始就返回 chunk 生成器，但 Phase 2–3 内部一次性 yield 完整音频，Phase 4 再换成真流式。**接口不变，实现替换**，避免后期改调用方。

### D6：单机

ASR / LLM / TTS 全在 RTX 5070 这台机器（WSL2 + Windows 双环境）。
- 无跨机协议设计
- Service 层不假设进程内调用，保留 HTTP 边界，便于将来拆分
- 显存预算按单机共存算：TTS 3.45GB + ASR 2GB = 5.45GB，余量 4.4GB

### D7：范围收敛

**做**：TTS 引擎、情绪控制、角色/声音管理、管理 API、Web 界面、性能优化
**不做**：ASR 重写、LLM 重写、固件重写、协议重设计

Phase 5 从"ESP32 联调"缩为"桥接验证"：
- 只做 `ws_bridge.py`（zjy14 引擎 ↔ zjy13 protocol v1）
- 24kHz PCM S16LE 单声道输出，固件已固定此格式
- 不重新烧录固件

### D8：完整 8 页

仪表盘 / 角色管理 / 声音管理 / 情绪管理 / 合成测试 / 设备管理 / 系统设置 / 日志中心。

情绪管理页是 D1 的关键可视化：并排试听 6 种情绪，直接支撑盲听决策。

### D9：单角色做深

- 角色 CRUD 功能照做（为将来准备）
- 当前只装 elysia 一个实例
- 重点验证：跨文本、跨情绪、跨会话的音色一致性
- 不做多角色串音色测试（原文档要求 3 个角色，**因素材不足降级，需在验收报告注明**）

### D10：默认 localhost + token

- 默认 `127.0.0.1:50001`
- 开启局域网需显式改配置，且**必须**设置 `auth_token`
- 未设 token 时拒绝监听 `0.0.0.0`（启动时报错，不静默放行）
- ESP32 联调：走 Windows 侧 `ws/server.py` 转发，不直连 zjy14

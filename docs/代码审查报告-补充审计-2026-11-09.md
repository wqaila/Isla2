## 三、复核后未采纳的条目

以下各项由单元提出，但复核后认为**不成立或证据不足**，故未写入主报告：

| 提出者 | 条目 | 不采纳的理由 |
|---|---|---|
| B | B-1 静默重试丢弃已吐字流 | `emitted` 是 `nonlocal`，每次尝试内被 `guarded_delta` 置真，`if emitted: raise` 在同一 `except` 内生效。**场景不成立** |
| C | N3 `app_audio_init` 返回成功后 `s_tx`/`s_rx` 仍为 NULL | 推论的起点是「IDF 对同一控制器两个通道模式不一致会断言」。该断言存在，但 `app_audio_init` 失败会返回错误、`app_main` 只打日志继续——这条更接近**错误处理缺失**而非独立缺陷，已并入 H 系列讨论，不单列 |
| C | N4/N5 分片缓冲尺寸问题 | 与 D 单元 `V03`（分片错位）和已知 `H4`（静态缓冲超配）重叠，且行号引用与实际代码（`.buffer_size = 16384`）不符，证据链不闭合 |
| A | N1 `asyncio.TimeoutError` 误判 | Python 3.11 中 `asyncio.timeout()` 与内建 `TimeoutError` 同类的判断正确，但「外层会把内层业务超时误判为整轮超时」缺少可复现路径，暂记为**待验证**而非问题 |
| A | N5 WAV 未校验声道 | 复核确认 `_wav_to_pcm16` 只查位深、不查声道，**问题真实**；但当前 TTS 服务固定输出单声道，退化路径暂未触发，故降级处理、未入主报告 |
| B | B-2 TTS 不校验 WAV 内容 | `_probe_wav` 失败会被吞掉返回 0，但落盘后的 `wave.open` 确会抛错——与 A-N5 属同一族（TTS 输出校验缺失），合并讨论 |

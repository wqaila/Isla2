## 四、性能与可维护性汇总

1. **zjy9 是全工作区最需要重构的部分**：`main.py` 单文件 1370 行，`/api/chat` 的处理逻辑在 REST 和 WebSocket 两条路径上**几乎完全重复**（历史构建、情感分析、学习引擎调用、记忆写入各写一遍），任何改动都要改两处，已经出现了 `history` 取错这种两边一起错的情况。建议抽出统一的 `handle_chat_turn()`。
2. **同步 I/O 阻塞事件循环**：zjy9 里日志写 SQLite、学习引擎写 JSON、TF-IDF 全量重写 JSON，全部发生在 async 请求路径上，且都是同步阻塞调用。并发上来后延迟会急剧劣化。
3. **配置系统是半成品**：`config.py`（常量）、`config_persistence.py`（JSON + 加密）、`cloud_client`（内存态）三处配置来源并存且不一致，读的地方各读各的，是最容易出隐性 bug 的结构。
4. **两份前端 HTML 分叉**（zjy9），改一份就漏一份。
5. **大量死代码/死配置**：`main_cli`、`set_device`、`merge_with_mergekit`、`kb_answer_map`、`template_str`、`data_path`、`slowapi`、`HEARTBEAT_INTERVAL`、`build_time_enhanced_context` 等，都是"写了但没接上"。

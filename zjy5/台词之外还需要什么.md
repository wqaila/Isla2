# 台词之外，训练一个角色模型还需要什么

> **这份文档为什么放在 zjy5**
>
> zjy5 是采集端。下面列的缺口里，有相当一部分**只能在采集端修**——
> 长度红线、说话人纯度、重复频次、句级溯源，一旦台词变成纯文本落盘就补不回来了。
> 采集端决定了上游数据形态，所以它得知道下游（zjy7）到底要什么。
>
> 数据基线：**2026-09-28 实测量化**（`zjy7/train_data.json`，1736 条）。
> 所有数字都来自实际跑脚本统计，不是估计。

---

## 一句话结论

台词只解决「**她说什么**」。要训出一个像样的角色，还得有：

| 还缺的东西 | 解决的问题 |
|------------|-----------|
| **人设（System Prompt）** | 她是谁 |
| **user 侧的提问** | 别人怎么问，她才该怎么答 |
| **知识库 / 事实** | 别让她编造自己没做过的事 |
| **负样本 / 边界** | 什么情况下不能顺着说 |
| **通用数据** | 别把基础能力训没了 |
| **多轮上下文样本** | 长对话里人设不崩 |
| **长度与风格约束** | 别又臭又长，也别只回三个字 |
| **评估集** | 知道训好了没有 |

## 二、每一项详解

### 1. 人设（System Prompt）—— 最关键

台词决定「怎么说话」，人设决定「是谁」。**两者必须来自同一处**。

- **之前的问题**：人设硬编码在三处，互相不一致 ——
  训练侧（`prepare_data.py`）不提「舰长」、写「第二位（最初的第一位）」；
  线上角色卡（`zjy9/server/characters/elysia.json`）提「舰长」14 处、写「第一位，编号Ⅰ」。
  线上推理时客户端发的 system 消息会顶掉 Modelfile 里那份，
  所以实际是「**学着一套、用着另一套**」。
- **当前状态**：已新增 `zjy7/persona.py`，训练与部署都从角色卡读；
  新增 `zjy7/check_persona.py` 做一致性自检（退出码 1=人设来源不一致，2=产物过期）。
- **待确认**：角色卡写「第一位，编号Ⅰ」，崩坏3 设定是「第二位（编号Ⅱ），
  英桀创立之初的第一位」。这句要不要改由你定，**改完必须重跑 `prepare_data.py`**。

### 2. user 侧的提问

训练样本是 `user → assistant` 配对，**台词只有右半边**。
user 侧靠 KB + 同义变体 + 模板生成，现在的问题是**坍缩**：
420 个唯一提问里，Top3 就占了 537 条（31%）。后果是模型对这几类提问特别顺，
换个问法就发懵。

补法：
- 削峰：把 Top3 各压到 30~40 条（现有 `KEY_QA_REPEAT` 机制调一下即可）
- 换问法：`SYNONYM_QUESTIONS` 扩充，同义问法铺开
- **更根本的来源**：真实用户问过什么，见第 7 条

### 3. 知识库 / 事实

已有 `identity / relationships / world` 三类手写 Q&A，这是角色不胡编的锚点。
可继续补：时间线、术语表、禁忌设定（哪些事她不知道、哪些不该说）。

> 注意别塞太多：知识库条目会变成训练样本，占比过高会让模型变成「百科问答机」。

### 4. 负样本与边界

「你是 AI 吗」「说句脏话」「扮演别人」「帮我写诈骗短信」这类要怎么回。
现在 20 条拒答样本，其中真正涉及身份澄清的只有 2 条 —— 角色很容易被一句话带出戏。

补法：扩到 80~100 条，覆盖四类：身份澄清、越界请求、OOC 诱导、安全边界。

### 5. 通用数据（防灾难性遗忘）

现在 **0 条**：1736 条全是角色数据。纯角色数据微调 2 轮，
基础理解力和安全对齐会退化（表现为「问啥都往角色上拐」）。

补法：混 10~30% 通用指令/常识数据（同一个 LoRA 里一起训）。

### 6. 多轮上下文样本

现在 **0 条**，而线上（zjy9）带 20 条历史 —— **训练/推理形态不匹配**，
这正是长对话里人设最容易崩的原因。

> 💡 **最好的来源就在项目里**：zjy9 有「对话导出（JSON / Markdown）」功能，
> 真实多轮对话是天然的多轮训练样本。
> 用法：导出 → 筛掉质量差的轮次 → 转成 `system/user/assistant/user/assistant…` 格式。
> 比凭空编造的多轮真实得多。

### 7. 长度与风格约束

线上角色卡要求「普通 15-30 字 / 日常 30-60 / 复杂最多 120」，
但训练集里 36 条 >300 字、**最大 7541 字**（超过 `max_seq_length 1024`，
训练时被截成半截话 —— 等于在教她说一半），243 条 <15 字。

补法：先删/切开那条 7541 字的；再把长度分布往角色卡约束上靠。
**这一项采集端能直接做**：`chibtaici --min-len/--max-len` 已经是长度红线，
超长按标点自动切开。

### 8. 评估集

已有 `eval_data.json` ✅。建议再加一个**人设一致性**维度
（用本地 Ollama 打分：像不像爱莉希雅 / 有没有 OOC / 长度是否超标），
`zjy7/evaluate.py` 里已有「角色一致性 + 脱角色检测」的架子可扩。

### 9. 说话人纯度（采集端专属）

台词里混着旁白和其他角色 —— 这就是**人设污染**，比数据少更糟。
现在可用 `chibtaici --speaker-filter` 做语气打标（本地 LLM 判「像不像角色本人」），
低分剔除。重型方案（pyannote 声纹聚类）暂不上。

## 三、建议顺序（按「收益 ÷ 成本」排）

| # | 做什么 | 成本 | 做完怎么验证 |
|---|--------|------|-------------|
| **1** | **人设统一到单一来源** | 已做 | `python check_persona.py` 退出码 0 |
| **2** | 砍掉超长样本、长度分布对齐角色卡 | 小 | `data_stats.py` 看分布；最大长度 ≤ 120 |
| **3** | 补多轮样本（优先用 zjy9 导出的真实对话） | 中 | 多轮样本占比 ≥ 15%；长对话不崩 |
| **4** | 混通用数据 10~30% + 负样本扩到 80~100 条 | 中 | 通用问题能正常答；诱导提问不脱角色 |
| **5** | 削提问峰值 + 用语气打标提纯度 | 中 | Top 提问占比 < 10%；抽样看台词是否都是本人 |

**第 1 步已经做完**（`zjy7/persona.py` + `check_persona.py`）。
下一步跑之前，先把这两条补上：

```bash
cd zjy7
python check_persona.py      # 现在是 exit 2：产物过期
python prepare_data.py       # 用新人设重新生成训练集
python deploy_ollama.py      # 重新生成 Modelfile
```

> ⚠️ `train_data.json` 是**快照**，换了人设不会自己变 ——
> 自检会告诉你「N/M 条与当前人设一致」，不是全一致就重跑。

## 四、采集端（zjy5）现在能直接贡献什么

| 能力 | 怎么帮到训练 |
|------|-------------|
| **`--format jsonl` 句级溯源** | 按置信度 / 通道过滤低质量句；出问题能回溯到具体 BV 号和时间点 |
| **频次统计**（`text_clean.text_frequencies`） | 高频台词是口头禅 → **加权采样**而不是一刀删；同时也用来发现提问坍缩 |
| **语气打标**（`--speaker-filter`） | 剔除不像角色本人的句子 → 人设污染的源头治理 |
| **长度红线**（`--min-len/--max-len`） | 直接产出合格长度，超长按标点切开，不再有 7541 字的连行 |
| **掐头去尾**（`--skip-head/--skip-tail`） | 去掉 OP/ED 歌词与片尾广告 |
| **规范化 + 去重** | 繁简/全半角统一，同一句不重复占位 |
| **批量字幕收割**（`--harvest`） | 同一句在不同视频里出现 → 天然的高频口头禅信号 |

**采集端做不到、得靠下游的**：user 侧提问、多轮上下文、负样本、通用数据 ——
这些不是台词，是「对话结构」，只能在 `prepare_data.py` 那一层生成。

## 五、附：2026-09-28 本次改动（zjy5 侧）

按「采集工具改进方向」的优先级做的：

| 项 | 落地 |
|----|------|
| 批量字幕收割 | 新增 `bilibili_downloader/harvest.py`：UP 空间 / urls.txt → 枚举 → 逐个探测 → 命中直接抄文本（不下载、不 OCR）。`--probe-only` 看命中率、`harvest_state.json` 断点续跑 |
| 频道分页 + `--max-count` | `get_all_channel_videos()`；播放列表默认 10 个的限制也接上了 |
| jsonl 结构化 | `--format jsonl/all`：`text/video/start/end/channel/confidence`，收割端与识别端字段对齐 |
| whisper 升级 | 默认 `base` → `large-v3`；VAD 切句；`--hotwords` 注入专有名词 |
| OCR 跳帧 | 区域指纹比对，实测跳过 **88%** 的 OCR 调用；OCR 条目有了真实持续时间 |
| 合并策略 | 改为「相同/相似/包含才算同一条」，不再拼连行、不再拼重复 |
| 采集质量红线 | 新增 `chibtaici/text_clean.py`：繁→简、全半角、去表情、4~100 字、超长切句、掐头去尾、去重记频次 |
| 语气打标 | 新增 `chibtaici/speaker_filter.py`：本地 Ollama 打 1-5 分，低分剔除；不可用时**不丢数据** |
| 测试 | 新增 `zjy5/tests/`：三个离线脚本（17 个测试函数）+ OCR 集成冒烟 |

两处刻意保留默认值的决定：`--require-complete` 默认关（ASR 常无标点，默认过滤会损失大量语料）；
`--skip-head/--skip-tail` 默认 0（默认掐头去尾会静默丢内容，推荐值写在文档里由你决定）。

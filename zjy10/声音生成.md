# Anime Voice Lab

**Windows + RTX 5070 + GPT-SoVITS 动漫角色声线复刻系统完整搭建流程**

---

## 一、项目目标

本项目的目标不是简单地实现：

```text
文字 → AI声音
```

而是搭建一个完整的：

> **动漫角色声线复刻与可控语音生成系统**

最终实现：

```text
选择角色
    ↓
选择情绪
    ↓
调整角色声线参数
    ↓
输入台词
    ↓
GPT-SoVITS生成
    ↓
声音后处理
    ↓
声音质量/相似度分析
    ↓
自动调参
    ↓
输出最终角色语音
```

最终系统名称可以暂定：

```text
Anime Voice Lab
```

## 四、为什么选择 GPT-SoVITS

本项目第一阶段使用 GPT-SoVITS，而不是同时安装大量声音模型。

主要原因是：

```text
Windows支持
+
少量参考声音
+
Zero-shot
+
Fine-tuning
+
中文支持
+
日文支持
+
适合声音克隆实验
```

因此：

> GPT-SoVITS 作为第一版系统的核心声音生成引擎。

以后可以再加入：

```text
CosyVoice
F5-TTS
其他TTS模型
```

作为备用引擎。

### 三个候选模型的对比

| 项目 | 安装门槛 | 中文表现 | 参考音频需求 | 特点 |
|------|----------|----------|--------------|------|
| **GPT-SoVITS** | **最低**（有 Windows 整合包） | 强 | 零样本 5～10 秒；微调 5～10 分钟 | 中文社区最活跃，教程最多，新手友好 |
| CosyVoice | 高（要自己配环境） | 强 | 零样本几秒 | 音质与流式更好，支持自然语言指令控制 |
| F5-TTS | 中 | 中 | 零样本十几秒 | 多语言，英文表现更好 |

**关键差异是"安装门槛"**：GPT-SoVITS 的 Windows 整合包解压即用，自带
Python / PyTorch / CUDA 环境，最快一小时内就能听到第一段声音。CosyVoice
音质可能更好，但环境配置本身就是一道坎，更适合"已经跑通、想再优化音质"
的阶段。这与第四十四节的开发原则（**先跑通**）是一致的。

## 五、理解"模型"和"角色声音"的区别

这是整个项目最重要的概念之一。

### 声音模型

例如：

```text
GPT-SoVITS
```

它相当于：

> 声音生成引擎。

### 角色声音

角色声音来自：

```text
reference.wav
```

或者经过训练得到的：

```text
角色专属模型
```

所以：

```text
GPT-SoVITS
+
参考声音
+
输入文本
=
新的角色语音
```

而不是：

```text
下载GPT-SoVITS
=
直接得到某个动漫角色声音
```

### 6.1 检查 NVIDIA 驱动

```bat

```

> ⚠️ **如果这一步报错，先别往下走。**
> 常见报错是 `Failed to initialize NVML: Unknown Error`。这说明驱动层面
> 有问题（或显卡未被正确初始化），此时即使把 PyTorch 装好，也用不了 GPU。
> 处理顺序：重启 → 重装/回滚 NVIDIA 驱动 → 再跑 `nvidia-smi`。
> **这是整条链路的地基，必须最先确认。**

## 七、安装 Python

建议：

```text

```

或者：

```text
Python 3.11
```

安装后：

```bat

```

然后：

```bat

```

确保 Python 和 pip 可以正常运行。

> ⚠️ **注意：`python` 和 `pip` 可能不是同一个 Python。**
>
> 实测本机就是 `python` → 3.13、`pip` → 3.11 混用。原因是 PATH 里可能
> 装了多个 Python（系统版、WindowsApps 版、各种软件自带的版本），
> `python.exe` 和 `pip.exe` 分别解析到了不同的安装。
>
> **对策**：不要依赖裸的 `python`，改用 `py` 启动器显式指定版本：
>
> ```bat
> py -0
> ```
>
> 这条命令会列出本机所有已安装的 Python。确认 3.10 或 3.11 在列表里，
> 后面统一用 `py -3.10` 调用。

## 二十五、人格参数

```text
可爱：9/10
温柔：7/10
活泼：9/10
高冷：2/10
成熟：3/10
攻击性：2/10
慵懒：2/10
元气：9/10
```

这些参数主要用于：

> 描述角色的声音和说话风格。

它们并不意味着 GPT-SoVITS 原生就能直接用一个"可爱度=9"的参数控制声音。

后面需要我们自己开发控制层。

### 控制层怎么实现：只有三条路

上面那套 0～10 的滑杆**不是模型的原生接口**。GPT-SoVITS、CosyVoice、
F5-TTS 这类零样本克隆模型只接受「**参考音频 + 文本**」，并没有这些旋钮。
所以"控制层"必须把参数映射到下面三条路之一：

| 手段 | 能控制什么 | 有效程度 |
|------|------------|----------|
| **换参考音频** | 情绪、语气、风格、音色 —— 几乎全部 | ★★★ 最有效 |
| **文本指令** | CosyVoice 支持用自然语言描述语气（GPT-SoVITS 支持有限） | ★★ |
| **后处理**（sox / praat） | 音高、语速、EQ 明亮度、加气声 | ★ 只能近似 |

**具体建议**：

- **"情绪"不要做成滑杆**，做成第二十八节的「每个情绪一条参考音频」。
  这比调数值自然得多 —— 情绪还体现在气声、共鸣位置上，那些后处理改不出来。
- **"音高 / 语速"** 可以直接映射到后处理，是少数能真正用数值控制的项。
- **"明亮度 / 厚度 / 气声"** 可以用 EQ 和激励器近似，但只能做粗调。
- **"可爱度 / 温柔 / 高冷"这类人格参数**无法直接控制，只能靠参考音频
  和训练数据体现。它们更适合作为**描述性标签**（用于选参考音频、做 A/B
  对比），而不是"旋钮"。

把这一点想清楚，可以避免做出一个"调了没反应"的参数面板。

## 二十八、参考音频选择系统

同一个角色可以准备多个参考音频：

```text
references/
├── normal.wav
├── happy.wav
├── angry.wav
├── sad.wav
├── shy.wav
└── surprised.wav
```

```text
角色：Character_A
情绪：Angry
```

系统自动选择：

```text
angry.wav
```

作为参考声音。

这样可以提高不同情绪状态下的表现稳定性。

> 💡 **这是整个方案里最有效的一招**，比任何数值参数都管用。
> 因为音色和情绪**都来自参考音频**——换参考音频等于同时换了音色和情绪，
> 而且用的是模型的原生能力，不需要跟模型"较劲"。

## 三十三、声音质量评价系统

建立：

```text

        VS
Generated Voice
```

```text

```

最终得到多个指标：

```text

语速差异
```

不要只用一个数字判断"像不像"。

> 多维度分析生成声音与目标声音之间的差异。

## 三十四、自动调参系统

完整流程：

```text
角色Profile
     ↓
GPT-SoVITS
     ↓
生成声音
     ↓
特征提取
     ↓
与目标Profile比较
     ↓
发现差异
     ↓
自动修改参数
     ↓
重新生成
```

例如：

```text
目标：

音高：8
明亮度：9
厚度：3

实际：

音高：6.8
明亮度：7.5
厚度：4.2
```

系统可以建议：

```text
音高 ↑
明亮度 ↑
厚度 ↓
```

然后再次生成。

> ⚠️ **这一步有个循环依赖要注意**：模型不接受"音高=8"这种输入
> （见第二十五节），所以"自动修改参数"改的其实是**后处理参数**
> （音高偏移、EQ、语速），而不是模型参数。想清楚这一点，闭环才落得了地。
>
> 另外"目标参数 0～10"本身是主观的、没有客观基准。所以这个系统更适合做
> **A/B 对比**（同一句话用不同参考音频生成，程序客观测出哪条更接近参考音频
> 的特征），而不是"绝对达标"。

## 四十七、版权与合规

这一节不属于技术流程，但**建议在动手前先想清楚**。

参考音频如果来自动漫角色，那实际上是**配音演员的声音**。声音在我国受
《中华人民共和国民法典》第 1023 条保护（参照适用肖像权保护的有关规定）。

区分两种情况：

| 用途 | 风险 |
|------|------|
| **个人自用**（自己电脑上生成、自己听） | 属于常见的研究/自用范畴，风险低 |
| **公开发布**（上传到公开仓库、分享给他人、商用） | 涉及他人声音权益，风险明显更高 |

**做法建议**：

- 克隆产物（参考音频、训练好的模型、生成结果）**不要随项目仓库分发**，
  只作为本地运行时资产。
- 如果项目要开源，仓库里只放**代码和流程文档**；用 `characters/`、
  `dataset/`、`models/`、`outputs/` 这些目录承载数据，并把它们加进
  `.gitignore`。
- 参考音频素材优先选**自己有授权**的，或明确允许二次创作的声音。

> 这一节不是劝退——个人本地玩是完全正常的技术探索。
> 只是"本地自用"和"推到 GitHub"之间有一条明确的界线，别不小心跨过去。

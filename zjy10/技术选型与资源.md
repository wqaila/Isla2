# Anime Voice Lab

**开源生态、模型资源与技术选型补充文档**

> 本文档是 Anime Voice Lab 项目的独立补充文档。
>
> 本文不重复项目主体流程，而是专门负责：
>
> - 调查现有成熟语音技术
> - 整理 GitHub、Hugging Face、ModelScope、论文等资源
> - 比较不同语音模型
> - 确定哪些能力直接复用
> - 确定哪些能力自己开发
> - 为后续模型替换和扩展提供技术依据

---

## 一、为什么不能只关注 GitHub

Anime Voice Lab 涉及的技术范围比较大。

如果只搜索：

```text
GitHub + voice cloning
```

很容易漏掉很多重要资源。

完整的技术生态应该包括：

```text
GitHub
│
├── 开源代码
├── WebUI
├── 推理程序
├── 训练程序
└── 项目源码

Hugging Face
│
├── 模型
├── Dataset
├── Demo
├── Space
└── 权重

ModelScope
│
├── 中文模型
├── 模型权重
├── 数据集
└── 国内镜像

论文
│
├── 新算法
├── 模型原理
├── 实验结果
└── 技术发展方向

官方 Demo / API
│
├── 在线体验
├── 商业模型
└── 闭源高质量模型

音频工具
│
├── FFmpeg
├── UVR
├── Demucs
├── VAD
└── ASR
```

因此 Anime Voice Lab 应采用：

> **"全生态选型，而不是 GitHub 单一来源选型。"**

## 三、第一核心：GPT-SoVITS

官方 GitHub：

https://github.com/RVC-Boss/GPT-SoVITS

### 3.1 项目定位

GPT-SoVITS 是 Anime Voice Lab 当前最重要的候选核心。

官方目前提供：

- Zero-shot TTS
- Few-shot TTS
- 多语言支持
- WebUI
- 数据集切分
- ASR
- 人声/伴奏分离
- 文本标注
- GPT/SoVITS 微调

官方 README 当前说明，零样本可以使用约 5 秒参考音频进行快速测试，少样本可以使用约 1 分钟数据进行微调。它目前支持中文、英语、日语、韩语、粤语等语言。

---

## 四、GPT-SoVITS 为什么适合第一阶段

Anime Voice Lab 第一阶段最重要的问题不是：

> "哪个模型理论上最先进？"

而是：

> "哪个模型能够让我最快建立一个稳定的本地语音生成基础？"

GPT-SoVITS 的优势在于：

```text
Windows
+
NVIDIA GPU
+
WebUI
+
参考音频
+
中文/日语
+
零样本
```

能够比较快地建立完整实验闭环。

而且官方目前已经提供 Windows 安装方式和 CUDA 环境说明，并列出了 Python 3.10/3.11、PyTorch 2.5.1/2.7.0 等测试环境。具体安装时仍然应该按照当时官方仓库的最新要求执行，而不是长期固定本文中的版本。

---

## 五、GPT-SoVITS 不应该被视为最终模型

虽然 GPT-SoVITS 是第一核心，但 Anime Voice Lab 不应该设计成：

```text
Anime Voice Lab
       ↓
只能使用 GPT-SoVITS
```

而应该：

```text
Anime Voice Lab
       ↓
Model Controller
       │
       ├── GPT-SoVITS
       ├── CosyVoice
       ├── Fish Speech
       ├── F5-TTS
       ├── OpenVoice
       ├── RVC
       └── Seed-VC
```

这样以后出现更好的模型时，只需要增加一个 Adapter，而不是重新开发整个系统。

https://github.com/fishaudio/fish-speech

## 十、RVC

RVC 的定位与 GPT-SoVITS 不完全一样。

GPT-SoVITS：

```text
文字
 ↓
声音
```

RVC：

```text
原始声音
 ↓
目标声音
```

因此 Anime Voice Lab 可以支持两种模式：

```text
模式 A
文本 → 角色声音

模式 B
自己的声音 → 角色声音
```

这样项目就从普通 TTS 工具扩展成了：

> **TTS + Voice Conversion 平台。**

项目：

https://github.com/Plachtaa/seed-vc

Seed-VC 可以作为 Voice Conversion 候选。

适合研究：

```text

Voice Conversion
      ↓
```

它可以与 RVC 进行比较。

最终可以设计：

```text
Voice Conversion Controller
       │
       ├── RVC
       └── Seed-VC
```

## 十二、模型候选池

因此第一版模型候选池可以建立成：

| 模型 | 类型 | 主要用途 |
| --- | --- | --- |
| GPT-SoVITS | TTS/Voice Cloning | 第一核心 |
| CosyVoice | TTS/Voice Cloning | 横向比较 |
| Fish Speech | TTS | 横向比较 |
| F5-TTS | TTS | 技术路线比较 |
| OpenVoice | TTS/VC | 风格/音色实验 |
| RVC | VC | 变声 |
| Seed-VC | VC | 变声比较 |

这类 TTS/VC 模型在近年的语音研究综述和模型列表中也经常被并列讨论，因此没有必要把项目技术路线锁死在单一模型上。

## 十三、音频处理：FFmpeg

项目：

https://ffmpeg.org/

FFmpeg 是基础设施，而不是 AI 模型。

负责：

```text
视频 → 音频
音频格式转换
采样率转换
裁剪
拼接
音量处理
编码
```

例如：

```text
anime.mp4
    ↓
FFmpeg
    ↓
anime.wav
```

Anime Voice Lab 应该直接调用 FFmpeg，而不是自己实现这些功能。

https://github.com/Anjok07/ultimatevocalremovergui

它主要用于：

```text

+
BGM
+
环境音
+
音效
```

```text
Voice
+
Instrumental
```

这对动漫角色数据集尤其重要。

## 十五、人声分离：Demucs

项目：

https://github.com/facebookresearch/demucs

Demucs 同样可以用于：

```text
音频
 ↓
人声分离
 ↓

```

可以与 UVR 做比较。

可以先测试：


## 十六、VAD

VAD：

> Voice Activity Detection

主要作用：

```text
长音频
 ↓
判断哪里有人说话
 ↓
自动切片
```

例如：

```text
00:00 - 00:03  BGM
00:04 - 00:07  台词
00:08 - 00:10  BGM
00:11 - 00:15  台词
```

自动得到：

```text
voice_001.wav
voice_002.wav
```

GPT-SoVITS 本身已经包含训练数据切分相关工具，因此第一阶段没有必要重新开发一套复杂 VAD 系统。

---

## 十七、ASR

ASR：

> Automatic Speech Recognition

作用：

```text
语音
 ↓
文字
```

例如：

```text
character_001.wav
```

自动得到：

```text
「你今天怎么来了？」
```

GPT-SoVITS 当前已经整合了多种 ASR/相关工具，包括 Fun-ASR-Nano、SenseVoice、FunASR 等。

因此第一阶段也不建议自己开发 ASR。

## 二十二、建立统一测试集

这是整个技术选型里非常重要的一部分。

不要：

```text
GPT-SoVITS 用一句话
CosyVoice 用另一句话
Fish Speech 又用另一句话
```

而应该建立固定测试集：

```text
test/
├── normal_01.txt
├── normal_02.txt
├── happy_01.txt
├── angry_01.txt
├── sad_01.txt
├── excited_01.txt
├── question_01.txt
└── long_sentence_01.txt
```

每个模型都使用：

```text
相同参考音频
+
相同文本
+
尽可能一致的测试条件
```

---

## 二十三、模型测试维度

不要只测试"像不像"。

建议记录：

| 指标 | 含义 |
| --- | --- |
| Timbre | 音色相似 |
| Naturalness | 自然度 |
| Emotion | 情绪表现 |
| Pronunciation | 发音准确度 |
| Rhythm | 节奏 |
| Pause | 停顿 |
| Stability | 稳定性 |
| Similarity | 角色相似程度 |
| Speed | 推理速度 |
| VRAM | 显存占用 |
| Setup | 部署难度 |

最终得到：

```text
Model Test Report
```

---

## 二十四、不要建立简单的"模型排名"

例如不要简单定义：

```text
GPT-SoVITS 第一
CosyVoice 第二
Fish Speech 第三
```

因为不同模型可能适合不同任务。

应该建立：

```text
任务
 ↓
模型表现
```

例如：

```text
角色音色克隆
        ↓
测试所有模型

情绪控制
        ↓
测试所有模型

中文
        ↓
测试所有模型

日语
        ↓
测试所有模型

实时变声
        ↓
测试 VC 模型
```

最后形成：

> **任务 → 模型适配关系**

而不是一个简单总排名。

## 二十七、Voice Profile

例如：

```text
Character A

Pitch:       8
Brightness: 7
Thickness:  3
Breathiness:6
Nasality:   2

Speed:      7
Clarity:    8
Pause:      5

Cute:       9
Energetic:  8
Mature:     2
```

需要再次强调：

> 这些 0～10 参数是 Anime Voice Lab 自己设计的控制层，不是 GPT-SoVITS 原生支持的"可爱度 9"参数。

真正的实现方式应该是：

```text
Voice Profile
      ↓
参数解释器
      ↓
参考音频选择
      ↓
模型参数
      ↓
后处理
```

### Phase 1：基础验证

只做：

```text
Windows
+
RTX 5070
+
GPT-SoVITS
+
参考音频
+

```

### Phase 2：模型横向测试

加入：

```text
GPT-SoVITS

```

建立统一测试集。

### Phase 3：角色系统

开发：

```text

```

### Phase 4：Voice Conversion

加入：

```text

Seed-VC
```

实现：

```text
自己的声音
 ↓

```

```text
 ↓

 ↓
```

## 四十二、最终结论

Anime Voice Lab 不应该被设计成：

```text
一个模型
+
一个 WebUI
```

而应该设计成：

```text
多个成熟模型
        +
成熟音频工具
        +
统一模型接口
        +
角色管理
        +
声音参数
        +
情绪系统
        +
参考音频系统
        +
数据集系统
        +
最终 Web UI
```

即：

> **底层复用整个开源语音生态，上层构建自己的 Anime Voice Lab。**

这样以后即使 GPT-SoVITS 出现新的版本，或者出现新的 TTS / VC 模型，也只需要替换或增加底层 Adapter，而不需要推翻整个项目架构。

因此当前最合理的开发路线是：

```text
第一步
GPT-SoVITS 跑通
        ↓
第二步
建立统一测试集
        ↓
第三步
比较 GPT-SoVITS / CosyVoice / Fish Speech / F5-TTS / OpenVoice
        ↓
第四步
确定不同任务适合的模型
        ↓
第五步
加入 RVC / Seed-VC
        ↓
第六步
开发 Character Manager
        ↓
第七步
开发 Voice Profile / Emotion Profile
        ↓
第八步
开发 Reference Selector
        ↓
第九步
开发 Model Controller
        ↓
第十步
开发 Anime Voice Lab Web UI
```

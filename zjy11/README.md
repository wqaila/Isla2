## 1. 需求与第一版边界

用户明确要求：使用截图中的 ESP32-S3 开发板，接入云端模型，先实现角色回答；本原型独立放在 zjy11。

沿用已确认的人格方向：保留爱莉希雅核心性格，理解现实话题，默认是朋友；不自动发展恋爱关系，不用卖萌和口头禅代替角色个性。

本方案将范围拆成两个里程碑：

- **M1，必做文字闭环**：串口输入一句话，ESP32-S3 联网发送，得到云端生成的角色回答，先在串口验证，再显示到屏幕。
- **M2，可选语音闭环**：按住触屏录音，松开上传，返回角色文字和普通合成语音，由屏幕与扬声器输出。M2 不是 M1 的前置条件。

M1 不需要麦克风、语音识别、语音合成或音色克隆服务。用户尚未指定语音必须属于第一版，因此不把三种云端服务同时接入作为起步要求。

最初规划阶段只保存方案。用户已确认运行电脑轻量网关，因此现在新增独立 Python 环境与网关实现；仍不申请服务、不在缺少配置时调用付费 API、不烧录或擦除设备，也不修改旧项目。

## 2. 开发板判断与硬件约束

### 2.1 已知规格

用户截图显示：

| 项目 | 规格 | 本原型用途 |
|---|---|---|
| 主控 | ESP32-S3R8，双核，最高 240 MHz | 联网、交互和外设驱动 |
| 内存与存储 | 8 MB PSRAM、16 MB Flash | 网络缓冲、录音、显示与固件 |
| 网络 | 2.4 GHz Wi-Fi | 连接局域网网关，不依赖蓝牙 |
| 显示 | 1.85 英寸，360 × 360，ST77916 | 展示角色名、状态和回复 |
| 触摸 | CST816S | M2 录音触发及简单控制 |
| 音频 | 双麦克风、编解码电路，截图描述含扬声器 | M2 录音和播放 |
| 其他 | QMI8658、PWR、BOOT、锂电池接口 | 第一版不开发传感器和电池管理 |

「电子徽章造型、CNC 铝合金外壳、双麦克风、ST77916、CST816S」与官方 **ESP32-S3-Touch-LCD-1.85B** 高度一致。但截图标题未显示完整后缀，不能据此确定实际板卡及 PCB 修订。

官方 B 型资料列出 ES8311 和 ES7210，以及扬声器焊盘；是否已装好扬声器仍需检查实物或订单配置。不得在未核实前购买特定阻抗喇叭或照搬其他 1.85 英寸版本的 GPIO。

### 2.2 实施前的硬件关卡

- 确认完整型号与 PCB 修订，选择匹配的官方示例和原理图。
- B 型官方文档将 PWR 定义为电源控制，不支持自定义；不将其用作聊天按键。
- BOOT 是启动配置引脚，第一版优先用触摸操作，不默认占用它录音。
- 回声消除相关硬件不等于软件已经实现全双工；M2 采用录音与播放分开的半双工。
- USB 供电先完成测试，不依赖电池，不猜测电池极性或外设接线。

ESP32-S3 不承担大语言模型推理。这里的「接入板子」是让板子成为联网终端，不是把云端模型权重下载进板子。

## 3. 三条可选路线

| 路线 | 优点 | 代价与限制 | 适用情况 |
|---|---|---|---|
| A：板子直接调用云端 API | 文字请求链路短，不需要电脑作为网关 | 云端密钥进入设备；角色和各家协议变化需要更新固件；语音接入后复杂度增加 | 个人临时试验，明确接受密钥暴露风险 |
| B：板子调用轻量网关，网关调用云端 | 密钥不下发到板子，改角色不用重刷固件，后续接语音方便 | 首轮测试需要电脑持续运行一个小服务 | **本方案推荐** |
| C：板子接入完整的现有陪伴后端 | 可复用旧系统的功能 | 现有记忆、画像和摘要增加依赖，也会影响单纯角色效果验证 | 基础链路成功之后再评估 |

推荐 B，但不直接依赖旧后端运行。网关在本项目内独立实现，起步只处理一个角色、一台板子和短期会话，不引入数据库、RAG、复杂智能体框架或管理后台。

**需要用户审阅的架构前提：首版允许电脑运行网关。**如果首版必须脱离电脑，方案应调整为部署云端网关，或在明确风险后选 A，不能把 B 描述成设备已完全独立。

## 4. 推荐架构：M1 文字闭环

```text
电脑串口终端输入文字（调试入口，不负责调用模型）
                    ↓ USB 串口
ESP32-S3：接收文字、连接 Wi-Fi、发送请求
                    ↓ 局域网
zjy11 轻量网关：校验设备、组装角色与短期历史
                    ↓ HTTPS
云端文本模型：生成角色回答
                    ↓
网关返回文字 → ESP32-S3 串口输出 / 屏幕显示
```

第一步用串口替代小屏幕中文输入法，避免先开发一套低效的触屏键盘。通过固定问题也能测试屏幕接收；串口阶段仍由板子实际发起网络请求，不以电脑直接调用模型替代硬件验证。

### 4.1 板端职责

- 连接已配置的 2.4 GHz Wi-Fi。
- 读取有长度上限的 UTF-8 串口输入，避免使用无限增长的字符串。
- 一次只处理一轮请求，不重复提交；显示连接、等待、完成或失败状态。
- 接收有大小上限的 JSON，解析角色回复。
- 优先串口确认正确，再启用屏幕中文显示、换行与滚动。
- 保存网关地址与可撤销的设备访问令牌，不保存模型服务商 API Key。

### 4.2 网关职责

- 校验设备令牌，限制请求大小、频率和并发。
- 从本地角色配置读取人格，每次请求都提供必要设定。
- 仅保存内存中的最近 4 轮成功对话，超上下文预算再减少旧轮次；重启或重置后清空。
- 只调用一个配置好的云端文本模型，不自动跨服务商回退。
- 返回回复、会话标识和错误信息，不把错误拼成角色台词。
- 不记录完整输入正文、模型提示词、密钥或设备令牌到默认日志。

第一版不做长期记忆，不导入旧项目数据库与画像。为了证明链路可控，可用「我叫小林」再追问称呼验证短期上下文，但不承诺跨重启记忆。

### 4.3 角色表达

角色配置包含核心人格、朋友边界、必要身份背景和 4 至 6 组短示例。示例覆盖日常、倾诉、反馈纠正和告别，不把剧情台词硬配成回答。

默认短回复，目标约 30 至 80 个汉字；复杂问题允许适度展开，模型输出预算单独限制。长度目标不是按字符在半句话中强行截断。屏幕和后续朗读不用依赖 emoji，也不直接展示 Markdown 标记。

重点约束：回应当前话题；温柔、自信、俏皮但不过度暧昧；可以坦率表达意见；不编造共同经历；未知事实不装作知道；不声称真人、实际在场或拥有未接入的工具能力。

「回答有角色特色」由人格与示例评测，不由是否包含「舰长」「嗯哼」判断。文字人格与配音演员原声是两回事，M1 不包含声音复刻。

## 5. 技术选择

### 5.1 固件

优先使用 **ESP-IDF + 微雪匹配板型的官方 BSP / 示例 + LVGL**，先复用已经验证的屏幕、触摸和音频驱动，不手工重写芯片驱动，也不搬用普通 ESP32 开发板引脚。

若实物确认为 B 型，其当前官方 ESP-IDF 页面要求 **V5.5.3 或以上**。实施时核对示例包要求并固定实际通过编译的版本，不凭网页截图中的其他版本混装依赖。

LVGL 与音频组件采用匹配示例的版本。第一阶段只启用必要外设；不加载唤醒模型、不启用蓝牙、不堆大动画。中文字体必须覆盖显示文本或提供缺字回退，不能只让英文状态正常就宣称支持中文。

### 5.2 网关与模型

网关建议使用 Python + FastAPI + HTTPX。模型通过 OpenAI 兼容文本接口接入，但需要核实具体服务商的参数、流式行为与输出限制，不能认为兼容名称就代表完全兼容。

优先使用用户已经拥有可用 API 凭据、能稳定访问、支持中文的服务商。DeepSeek、通义等可作为候选，先选一个，不同时接多家。本方案不预定模型排名、现价或现有账号是否具有开发者 API 权限。

DSH 中能聊天不等于此硬件项目已经获得服务商 API Key。没有凭据时只运行离线模拟，不自动调用当前工具会话的账号路由充当产品服务。

### 5.3 网络

初期网关运行在与板子相同的可信局域网，建议端口 `8111`，实施时检查占用。板子使用电脑实际局域网地址，不使用 `localhost` 或 `127.0.0.1` 连接电脑。

调试时可在隔离可信网络中显式使用 HTTP，但令牌和对话在此链路上没有传输加密；不能暴露到公网，也不能称其为安全部署。非可信网络或云端网关必须使用 HTTPS 和正常证书校验，不用关闭证书验证来绕过错误。

跨网段、访客 Wi-Fi 的设备隔离、电脑防火墙和系统代理均属于连通性检查项；不会在本次方案阶段自动修改这些配置。

## 6. 建议接口契约

以下是准备在本项目实现的新接口，不是宣称旧项目已经提供这些路径。

### 6.1 文字对话

`POST /v1/chat`，通过 `Authorization: Bearer <device-token>` 鉴权，请求正文示例：

```json
{
  "request_id": "unique-request-id",
  "session_id": null,
  "message": "今天有点累，想和你聊聊。"
}
```

成功响应包含 `request_id`、网关分配的 `session_id` 和 `reply`。会话绑定当前设备令牌，不能凭客户端提交的会话标识读取别的会话。模型和角色由网关配置，不接受普通设备任意改写系统提示词。

第一版返回一次完整 JSON，不在板端解析云端流式事件。响应上限建议 8 KiB，输入上限建议 512 个 UTF-8 字节，最多一个进行中的请求；这些是实现默认值，需要真实中文测试验证。

网关按设备与 `request_id` 对近期请求去重，相同标识不再次发起模型调用；相同标识但不同内容应拒绝。请求超时结果未知时不自动生成新标识反复重试，先显示失败并允许用户明确操作。

### 6.2 错误与重置

- 未连接网络、鉴权失败、限流、网关不可达、模型超时和无有效回复分别返回可识别状态。
- 网关调用总超时建议 45 秒，板端等待预算建议 60 秒；长请求不阻塞界面事件或触发看门狗。
- `POST /v1/session/reset` 清空当前授权会话的短期历史，用于重新测试角色。
- 错误不进入短期历史；明确标记超时与失败，不能把技术异常改写为角色撒娇。
- 断网恢复后回到可操作状态，不自动重新发送可能已经计费的上一轮。

## 7. M2：按住说话与语音回答（可选）

M1 成功且用户确认需要语音后，再加入这条链路：

```text
触屏按住录音 → 松开上传音频
          ↓
网关调用语音识别（ASR）取得文本
          ↓
相同的角色文本模型生成回复
          ↓
网关调用语音合成（TTS）取得普通中文语音
          ↓
板子显示文字、播放语音
```

语音版增加 ASR 和 TTS，不应误认为所有文本模型 API 都能接收麦克风音频或输出语音。优先选择有正式接口与可用凭据的语音服务，不把非官方消费端接口当作产品保证。

- 初版半双工：播放时不录音，不做唤醒词、插话打断或边说边听。
- 优先触屏按住录音，不接管电源键；支持取消和最长 10 秒自动结束。
- 上传目标格式为 16 kHz、16-bit、单声道 PCM WAV。驱动实际采集可能是多声道、32-bit，需要按匹配示例正确转换，不能只改 WAV 文件头。
- 10 秒这种格式的 PCM 净数据约 320,000 字节，不含 WAV 头；8 MB PSRAM 不代表这些内存都可用，录音、显示、Wi-Fi 和音频 DMA 必须共同预算。
- 下载音频先统一为支持的 PCM WAV，板端分块读取播放，避免把长音频整体载入内存；不通过 Base64 把音频塞进 JSON。
- 音频下载沿用鉴权并限制可访问范围，不能提供可枚举的公开录音目录；临时音频完成后短期清理，不默认存私人录音。
- ASR 无有效文本时不调用模型；TTS 失败时仍保留文字回答，并提示本轮未能播放。
- 音色先用合法可用的普通女声；角色文字特色不依赖未经授权的配音演员音色克隆。

语音模式会叠加录音、上传、识别、生成、合成和播放等待。先测实际分段耗时，不预先承诺实时响应。

## 8. 开发顺序与验收

| 阶段 | 工作 | 通过标准 |
|---|---|---|
| 0：硬件基线 | 核对型号、工具链，运行匹配官方显示和触摸示例 | 实物显示正常、触摸可用、无反复重启 |
| 1：云端角色 | 先在网关调试文本，使用离线响应测试错误路径，再用批准的 API 实测 | 回答相关，保持朋友型人格，错误和正常回复分开 |
| 2：板端联网 | 串口输入，由板子请求网关并接收回复 | 串口能看到真实云端角色回答；无重复提交 |
| 3：屏幕输出 | 显示状态与中文回复，处理换行滚动 | 360 × 360 屏幕文字可读、不裁切，长回复不会撑坏界面 |
| 4：可选语音 | 先验证本地录音回放，再加入 ASR 和 TTS | 一次完整录音到角色播报闭环，失败可回到可操作状态 |

M1 验收场景至少包括：问候、倾诉、现实求助、称呼修改、不同意见、短期信息追问、告别、身份真实性、断网、鉴权失败和模型超时。

在板子上连续完成 10 轮对话，无重启、明显内存持续增长、会话串号或界面卡死。记录实际网关模型、角色配置版本、耗时、服务商返回的用量；无法获取用量时标未知，不以零代替。

这些是未来验收标准。本次没有进行编译、烧录、录音、云端调用或硬件运行验证。

实施时配置模板只使用占位值，真实 Wi-Fi 密码、设备令牌、云端密钥、录音、临时音频和构建产物排除出版本控制。API 凭据和费用上限由用户另外确认。

## 10. 决策与实施前提

本方案推荐：**M1 文字角色回答 + 独立轻量网关 + 官方 ESP-IDF 驱动基线**；M2 语音作为下一步，不把完整陪伴系统提前搬进来。

实施前需要完成三个关卡：

1. 用户确认是否接受电脑运行网关；如果不接受，先调整部署路线。
2. 核实实物完整板型与 PCB 修订，不能仅按截图烧录。
3. 真实云端调用前确认服务商、具体模型、API 凭据和测试费用上限。

当前状态：用户已要求运行电脑轻量网关，网关已独立实现；硬件完整型号与 PCB 修订仍须在烧录前核实。真实云端调用仍需配置具体模型和 API Key，并明确开启调用。本文不授权公网部署或设备擦除。实际运行与验证记录见 [RUNNING.md](RUNNING.md)。

## 2. 为什么必须确认完整型号

同为 1.85 英寸，微雪文档里至少存在三个易混淆的产品：

| 型号 | 音频差异 | 本版影响 |
|---|---|---|
| ESP32-S3-Touch-LCD-1.85B | ES8311 + ES7210，双麦克风，带回声消除 | 与截图最接近 |
| ESP32-S3-Touch-LCD-1.85C V1 | PCM5101，单麦克风，无回声消除 | 引脚不同，不可混用 |
| ESP32-S3-Touch-LCD-1.85C V2 | ES8311 + ES7210 | 引脚与 B 型也不同 |

用户截图写的是「ESP32-S3R8、8 MB PSRAM、16 MB Flash、ST77916、CST816S、双麦克风、QMI8658、CNC 铝合金外壳、电子徽章造型」，与 B 型描述高度吻合。但截图标题没有后缀，不能直接当作 B 型烧录。

**型号不是文字版的关键阻塞**：文字版只用屏幕、触摸和 Wi-Fi。但它决定屏幕驱动参数、引脚和官方示例分支，猜错会导致黑屏或触摸失效。

### 2.1 如何确认型号

按可靠性从高到低：

1. **PCB 丝印**：拆开外壳看板边丝印，B 型与 C 型 V2 都标有 `Rev` 版本。这是最可靠的依据。
2. **订单或包装标签**：电商订单页的完整商品名称、SKU 或包装盒标签。
3. **出厂固件画面**：B 型出厂固件会显示产品标识；C 型 V2 带 `Rev2.0` 标识。
4. **卖家确认**：把本文件第 2 节的型号差异表发给卖家核对。

拿到型号后，把完整名称填进本文档第 5 节，再选择对应官方示例。

## 3. 开发环境方案

### 3.1 推荐：项目内独立安装

工具链放在 `zjy11/.toolchain/` 下，不写入系统环境，不与其他项目共用：

- ESP-IDF 固定在已确认的版本，避免示例与框架版本不匹配。
- 所有下载与构建产物都在本项目内，便于清理和回滚。
- 不修改系统 `PATH`，不污染用户级环境变量。

官方 B 型页面要求 ESP-IDF **V5.5.3 或以上**。工具链版本一经确认运行通过，就写进文档固定下来。

### 3.2 安装内容

| 组件 | 作用 |
|---|---|
| ESP-IDF 源码 | 框架、官方示例与构建系统 |
| xtensa-esp32s3 工具链 | 编译 ESP32-S3 固件 |
| CMake + Ninja | 构建 |
| esptool | 烧录与读芯片信息 |
| Python 虚拟环境 | 供 idf.py 使用，与网关环境隔离 |

### 3.3 安装前需要知道

- 安装会下载数百兆到数 GB 的内容，耗时取决于网络。
- 安装命令必须显式指定目标芯片为 `esp32s3`，否则会装错架构。
- 安装完成后必须验证 `idf.py --version` 与 `idf.py set-target esp32s3` 可用。
- 本机此前出现 pip 写用户缓存停滞，安装步骤会显式关闭缓存并把临时目录放进项目内。

## 4. 板子接入后的第一步验证

板子插上后，先只做可读验证，不写业务代码：

1. 确认系统出现新的 COM 口。
2. 用 esptool 读取芯片信息，核对型号与 Flash 大小。
3. 烧录对应官方屏显示例，确认显示正常。
4. 跑触摸示例，确认坐标与点击可用。
5. 跑 Wi-Fi 示例，确认能连上 2.4 GHz 网络。

这五步都通过，再进入「串口文字接入网关」。任何一步失败都先停下查根因，不要在不确定的驱动上继续叠加功能。

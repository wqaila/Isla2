# ESP32-S3 文字版固件骨架（进行中）

> 归属：zjy11 第一版，见 [2026-10-19-v1-features.md](../docs/2026-10-19-v1-features.md)
> 状态：骨架与协议已实现，**尚未编译、尚未烧录、尚未在实物上运行**

## 1. 当前能做什么

```text
串口输入一行中文
      ↓
板子带设备令牌 POST /v1/chat
      ↓
电脑网关（已实现并运行）
      ↓
云端文本模型
      ↓
屏幕显示角色回答
```

第一版只有文字：串口输入、屏幕输出，不含录音与播放。

## 4. 与网关的严格对齐

固件不自行发明协议，常量必须与网关一致，由 `tests/test_firmware_contract.py` 交叉校验：

| 项目 | 值 | 来源 |
|---|---|---|
| 消息最大字节 | 512 | 网关 `ChatInput` 校验 |
| 请求体上限 | 2048 | 网关中间件 |
| 响应上限 | 8192 | 网关响应断言 |
| 鉴权 | `Authorization: Bearer <设备令牌>` | 网关 `authorize` |
| 对话 | `POST /v1/chat` | 网关路由 |
| 健康检查 | `GET /health` | 网关路由 |
| 重置 | `POST /v1/session/reset` | 网关路由 |

错误码同样以网关为准，固件只做「码 → 中文提示」映射，不解析网关的中文文案。

## 5. 安全边界

- 固件只保存**设备令牌**，绝不保存模型 API Key。
- 不把完整请求或令牌打印到串口日志。
- 网关地址必须是局域网 IP，不能用 `127.0.0.1`。
- 第一版是明文 HTTP，仅限可信局域网；公网需另行设计 HTTPS。

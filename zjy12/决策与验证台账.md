## 一、决策台账（D01–D20）

|---|---|---|---|---|

## 四、本轮（2026-10-22）新增的 8 条结论

| # | 结论 | 一句话依据 |
|---|---|---|
| 1 | **decode 已到物理上限** | 672 GB/s ÷ 5.7GB = 118 tok/s 理论上限，实测 96 → 效率 81% |
| 2 | **语音场景下 decode 不是瓶颈，prefill 才是** | 50 字 = 35 token = 0.36s；而 1000 token 人设的 prefill 是 0.5–1.25s |
| 3 | **`Qwen3.5-9B` 与 `-gguf` 不是两个模型** | 前者是 fp16 原始权重（~18GB，12GB 装不下），后者是同一模型的 Q4_K_M |
| 4 | **12GB 的天花板是 9B 级 dense** | 27B 即使 Q4 也 17.74GB；Gemma 4 26B-A4B ≈17GB；GLM-5.1 744B |
| 5 | **多机做模型并行反而更慢** | TP=2 每 token 64 次 all-reduce → 1GbE 下 96→36 tok/s |
| 6 | **混合云端不能提速，只能提可用性** | 本地 0.2–0.35s 本来就快过云端 0.3–0.8s，还省一次公网 RTT |
| 7 | **现有 LoRA 是 Qwen2.5-7B + Q8_0，跨了两代** | `merged_model/config.json` 为 `Qwen2ForCausalLM`/28 层/3584；file_type 7 = Q8_0 |
| 8 | **LoRA 与"单机跑全套"是否冲突取决于量化档** | Q8_0 8.1GB → 13.6GB 装不下；重量化 Q4（~4.4GB）→ 9.9GB 可行 |

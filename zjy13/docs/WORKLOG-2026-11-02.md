### 5. 固件缺陷修复（今天的重点）

#### 5.1 `TALK STOP` 崩溃（IllegalInstruction）

- **现象**：说完话松手（`TALK STOP`）后板子崩溃重启。
- **定位**：用 `addr2line` 解析崩溃地址 → 落在 `voice_client.c` 的 `record_loop`，崩溃指令是函数结尾的 `retw.n`，且返回地址寄存器 `A0 = 0`。
- **已排除**：栈溢出。加日志测得 `stack_hwm=5840`（余量充足）；把栈从 4096 加到 8192 后依旧崩溃。
- **修复**：
  - `record_loop` 末尾显式 `vTaskDelete(NULL)`，绕开异常的函数返回路径；
  - 任务结束前清理 `s_task` 句柄（原先任务自删后句柄悬空，导致下一轮 `vTaskDelete(s_task)` 命中已释放的 TCB，属于 use-after-free）。
- **验证**：连续多轮 `TALK/STOP` 未再崩溃。

#### 5.2 播放只播 1 秒就停

- **现象**：服务端已下发 100+ 帧音频，板子只收到约 12 帧就卡在 `PLAYING`，永远回不了 `playback_done`。
- **定位**：`ws_event` 的二进制分支（`op_code == 0x02`）**没有做分片重组**，把每个 WebSocket `DATA` 事件都当成完整帧。实测一个 4108 字节的音频帧被拆成 `payload_offset = 0 / 204 / 412 / 620 / 1036 / 3708` 多个事件，于是 `magic` 校验失败、`seq` 从 0 跳到 5 跳到 30。
- **修复**：仿照文本分支，用 `payload_offset` / `payload_len` 累积重组后再交给帧解析。
- **验证**：`seq` 变连续（0/1/2）；服务端 134 帧 / 547200 字节，板子收到 **134/134 帧、547200 字节，完全一致**；播完回到 `IDLE`。

> 这两个缺陷很可能就是此前 `FAULT-blackout-and-playback.md` 里「音频下发与连接关闭同一毫秒」现象的真正原因，而非文档原先推测的供电/热点问题。

### 7. 长音频下行中断修复（11-04 第二轮）

**现象**：16s 以上的长音频下发时偶发 `transport_poll_write` 超时 → 断连 → 轮次取消。

**根因**：服务端 `for off in range(...): await send_audio(...)` 是**无节流全速推送**，16 秒音频（约 780KB）几秒内灌满链路，WiFi Direct 承受不住。

**修复（两处配合）**：

1. `.env`：`LLM_MAX_TOKENS` 256 → **128**（角色卡本就要求"一句不超过 30 字"，256 给了太多余量，导致偶发长回复）
2. `server.py`：音频下发改为**按播放进度节流**

```python
lead_sec = 2.0                              # 允许领先播放进度 2 秒
for off in range(0, len(pcm), step):
    played_sec = time.perf_counter() - play_start
    sent_sec = (off + step) / bytes_per_sec
    ahead = sent_sec - played_sec
    if ahead > lead_sec:
        await asyncio.sleep(ahead - lead_sec)
    await self.send_audio(client, pcm[off:off + step], seq)
```

**配套**：板子播放环形缓冲从 20 秒降到 **8 秒**（`PLAY_MAX_SECONDS`），节流后不再需要容纳整段音频，同时降低 PSRAM 压力。

**效果**：连续 5 轮（含 16.08s 长音频）**0 崩溃、0 transport 错误、0 下发失败**。

| 音量 UI | 新增 `badge_dashboard_volume()`，语音状态行显示「语音待命 60」 | ✅ `VOL` 改音量后 100ms 内刷新 |
| 长按手感 | `lv_indev_set_long_press_time(300)`（原默认 400ms） | ✅ 更跟手，仍能区分短按/长按 |
| 内存/LCD 稳定性 | 连续 5 轮压力测试 + 逐轮内存采样 | ✅ 内存无泄漏（47.5~50.4KB 稳定）；LCD 报错为 BSP 已知限制 |

**关于 LCD 的 `ESP_ERR_NO_MEM`**：属第三方 BSP/LVGL 组件的 SPI DMA 内存竞争，播放期间屏幕会掉帧/花屏，**不影响语音链路**。曾尝试"播放时暂停动画重绘"，实测无效且导致角色僵住，已回滚。记录为已知限制，不做进一步侵入式修改。

### 5. 固件缺陷修复（今天的重点）

#### 5.1 `TALK STOP` 崩溃（IllegalInstruction）

- **现象**：说完话松手（`TALK STOP`）后板子崩溃重启。
- **定位**：用 `addr2line` 解析崩溃地址 → 落在 `voice_client.c` 的 `record_loop`，崩溃指令是函数结尾的 `retw.n`，且返回地址寄存器 `A0 = 0`。
- **已排除**：栈溢出。加日志测得 `stack_hwm=5840`（余量充足）；把栈从 4096 加到 8192 后依旧崩溃。
- **修复**：
  - `record_loop` 末尾显式 `vTaskDelete(NULL)`，绕开异常的函数返回路径；
  - 任务结束前清理 `s_task` 句柄（原先任务自删后句柄悬空，导致下一轮 `vTaskDelete(s_task)` 命中已释放的 TCB，属于 use-after-free）。
- **验证**：连续多轮 `TALK/STOP` 未再崩溃。

#### 5.2 播放只播 1 秒就停

- **现象**：服务端已下发 100+ 帧音频，板子只收到约 12 帧就卡在 `PLAYING`，永远回不了 `playback_done`。
- **定位**：`ws_event` 的二进制分支（`op_code == 0x02`）**没有做分片重组**，把每个 WebSocket `DATA` 事件都当成完整帧。实测一个 4108 字节的音频帧被拆成 `payload_offset = 0 / 204 / 412 / 620 / 1036 / 3708` 多个事件，于是 `magic` 校验失败、`seq` 从 0 跳到 5 跳到 30。
- **修复**：仿照文本分支，用 `payload_offset` / `payload_len` 累积重组后再交给帧解析。
- **验证**：`seq` 变连续（0/1/2）；服务端 134 帧 / 547200 字节，板子收到 **134/134 帧、547200 字节，完全一致**；播完回到 `IDLE`。

> 这两个缺陷很可能就是此前 `FAULT-blackout-and-playback.md` 里「音频下发与连接关闭同一毫秒」现象的真正原因，而非文档原先推测的供电/热点问题。

### 6. 音量与交互改进

- **音量**：播放音量默认从 `30` 提到 `60`，并新增串口命令 `VOL <0-100>`（`VOL` 单独发送为查询），运行时可调，无需重新烧录。

### 7. 内部内存优化（修复自己引入的问题）

- **问题**：早期为排查崩溃而加大任务栈、并新增静态缓冲，约多占 17KB 内部 RAM，导致内部可用内存只剩约 **39KB**，LCD 的 SPI DMA 申请缓冲失败，串口被 `ESP_ERR_NO_MEM` 刷屏。
- **处理**：既然已验证栈不是崩溃原因，把栈还原（`record_loop`/`play_task` 4096、心跳 3072），分片重组缓冲改从 **PSRAM** 分配。
- **结果**：内部可用内存约 **39KB → 78KB**，LCD 报错完全消失。

---

### 8. 屏幕文字方框（字库缺字）

- **现象**：长按屏幕时，底部语音状态文字显示为方框（豆腐块）。
- **原因**：语音状态文字使用精简字库 `badge_ui_14`，该字库仅按固定字符表生成（只有 81 个字符），**缺少「语、音、命、听、说、回、应」**。四个状态文案「语音连接中 / 语音待命 / 在听你说 / 正在回应」因此缺字。
- **修复**：用工程自带的 `SourceHanSansSC-Normal.otf` **重新生成 `badge_ui_14.c`**，在原有 81 个字符基础上追加上述 7 个字（81 → 88 个字符），保留原有字符及 ASCII 范围，文案代码未改。
- 生成工具：`lv_font_conv`（经 `npx lv_font_conv@1.5.2` 调用）。

## 三、走过的弯路与犯过的错误（如实记录）

1. **误判崩溃为栈溢出**：把 `record_loop` 栈从 4096 加到 8192，实测仍崩；后来用 `stack_hwm` 证明栈余量充足。加大栈属无用功，反而挤占内存。
2. **误判 `ui_sync()` 为崩溃原因**：把这个调用移出 `record_loop` 后依旧崩溃，判断错误。
3. **自己引入了内存问题**：上面两项改动叠加，使内部 RAM 紧张、LCD 刷屏报错，之后又花时间收回。
4. **对 hosts 被篡改一度困惑**：`github.com` 全域名被指向 `127.0.0.1`，一度按网络问题排查；后来才确认是 hosts 被改写。
5. **B 方案（云端配对）判断过于乐观**：以为可按端点复刻，实际卡在邮箱登录与缺失的「电脑工作端」，浪费了探索时间。
6. **早期把问题想简单**：曾以为新固件"改个地址就能连本地服务"，实际协议、鉴权、架构完全不同。

以上弯路多数通过**对照实测数据**纠正（`stack_hwm`、`addr2line`、`bin ev` 分片日志、服务端帧数/字节数对账）。

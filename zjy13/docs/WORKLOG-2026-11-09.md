## 三、第 12 项：TTS 启动卡住 / 文本前端静默失效（wetext）

### 现象

首次跑 `serve_tts_wsl.sh` 时，日志停在：

```
Downloading Model to directory: /home/user/.cache/modelscope/hub/pengzhendong/wetext
Downloading [en/tn/verbalizer.fst]: 100%|...| 5.99M/5.99M [01:01<00:00, 103kB/s]
Downloading [es/itn/tagger.fst]:   0%|...| 0.00/2.10M
```

之后**十几分钟没有任何进展**，`/health` 一直不通。

### 排查过程

**第一步：确认模型是否真的没下完。**

模型缓存在 `~/.cache/modelscope/hub/pengzhendong/wetext`，实测：

```
清单条目: 53
磁盘存在且非空: 52
缺失或 0 字节: 1  → __init__.py（0 字节，正常空包标记）
fst 文件数: 48
总大小: 66M
```

用 `.msc`（ModelScope 下载清单）逐条比对，**所有 fst 都已完整落盘**，
且 fst 魔数一致（`d6fdb27e`），没有损坏。

**关键发现**：清单里的语言目录只有 `['ar','de','en','ja','zh']`，**本来就没有 `es`**。
日志里那个 `es/itn/tagger.fst` 是下载器按远端全量清单轮询，本地并不需要。

所以：**模型是完整的，卡住不是在下模型。**

**第二步：直接构造 `Normalizer` 看真实报错。**

```python
from wetext import Normalizer
Normalizer(lang="zh", operator="tn")
```

```
HTTPError: Authentication token does not exist
```

**第三步：读源码确认机制。**

`wetext/wetext.py`：

```python
if tagger_path is None or verbalizer_path is None:
    repo_dir = snapshot_download("pengzhendong/wetext")   # ← 需要 ModelScope 鉴权
```

`CosyVoice/cosyvoice/cli/frontend.py`：

```python
try:
    import ttsfrd                      # ← 未安装
    ...
except:
    try:
        from wetext import Normalizer as ZhNormalizer
        self.zh_tn_model = ZhNormalizer(remove_erhua=False)   # ← 无参 → 联网
        self.en_tn_model = EnNormalizer()
        self.text_frontend = 'wetext'
    except:
        self.text_frontend = ''        # ← 异常被吞，静默降级
        logging.info('no frontend is avaliable')
```

### 根因

1. `Normalizer()` 不传路径时必定调 `snapshot_download()`，需要 ModelScope token
2. 本机没有 token → `HTTPError`
3. 该异常被 CosyVoice 的 bare `except` **吞掉**
4. 结果：**服务能启动，但 `text_frontend = ''`**，中文数字完全不做正则化
5. 弱网下 `snapshot_download` 会反复尝试鉴权，表现为「卡在下载」

**这是一个静默失效**：健康检查正常、服务能合成、听起来也没报错，
只是 "128" 会被读成 "一二八" 而不是 "一百二十八"。

### 修复

`Normalizer` 支持直接传 `tagger_path` / `verbalizer_path`，绕过 `snapshot_download`。

在 `tts_server_wsl.py` 里新增 `_patch_wetext_offline()`，给 `wetext.Normalizer`
套一层，把缺省的路径参数替换成本地 fst。调用位置必须在 `import cosyvoice` **之前**。

踩到的额外约束：一旦传了路径，`lang` 就必须是 `"en"` 或 `"zh"`：

```python
assert lang in ("en", "zh"), "Language must be 'en' or 'zh' when using custom tagger and verbalizer."
```

而 CosyVoice 两次调用都不带 lang（默认 `"auto"`），所以补丁还要修正 lang。
两次调用靠线索区分：

| 调用 | 线索 | 判定 |
|---|---|---|
| `ZhNormalizer(remove_erhua=False)` | 带 `remove_erhua` | zh |
| `EnNormalizer()` | 无中文线索 | en |

### 验证

**加载耗时**：

| 方式 | 耗时 | 联网 |
|---|---|---|
| 原（`snapshot_download`） | 卡住 >10 分钟 | 是 |
| 补丁后（本地 fst） | **0.01~0.09 秒** | 否 |

**日志确认**（关键对比）：

```

修复后：use wetext frontend
```

且启动日志里**完全没有 Downloading**，模型加载 9.2s + 预热 3.76s。

**文本前端真的生效**（ASR 回读对照）：

| 这个要**一百二十八**块钱，今天气温**二十三**度（对照组） | 这个要一百二十八块钱今天气温二十三度 |

**端到端**（WS 模拟器，真实 ASR + LLM + TTS）：

## 四、第 11 项：一键启动 TTS + WS

### 问题

原本演示要手工开两个终端、按顺序启动，还要自己判断 TTS 有没有加载完。
**顺序错了（WS 先起）会直接退出码 2**，因为 WS 启动时会做 TTS 健康检查
（这是 V2 要求的「不得静默回退云端」），但用户看到的只是一个退出码。

### 实现

`scripts/start_all.ps1` + 双击入口 `一键启动.bat`：

```
前置检查（Python / .env / Clash 代理 / 热点）
  → WSL2 起 TTS，轮询 /health 直到就绪
  → 起 WS 服务端，确认端口监听
  → 打印地址
```

参数：`-BindHost` / `-WSPort` / `-TTSPort` / `-TTSTimeout` /
`-SkipTTS` / `-SkipWS` / `-NoHotspotCheck` / `-Status` / `-Stop`

### 写这个脚本时踩到的 4 个坑（都已修，并有测试锁住）

#### 坑 1：无 BOM 的 UTF-8 中文脚本被 PowerShell 按 GBK 解码

现象：`ParseFile` 报 3 个语法错误，位置在第 177、220、228 行，
但那些行本身完全合法；`Get-Content -Encoding UTF8` 读出来也正常。

对比实验定位：

| 方式 | 错误数 |
|---|---|
| `Parser::ParseFile(路径)` | **3** |
| `Parser::ParseInput(Get-Content 读入的文本)` | **0** |

根因：Windows PowerShell 5.1 的 `ParseFile` 对**无 BOM** 的 UTF-8 文件
按系统 ANSI（本机 GBK）解码，中文注释被解成乱码后破坏语法分析，
报出的位置与真实原因无关。

修复：脚本保存为 **UTF-8 with BOM**。测试 `test_ps1_has_utf8_bom` 锁住。

> 注意：编辑工具重写文件会去掉 BOM，所以每次改完都要确认。
> 这也是为什么测试里要断言 BOM 存在。

#### 坑 2：`Get-NetTCPConnection` / `Get-NetIPAddress` 在受限权限下「拒绝访问」

现象：Clash 明明在 7897 监听（`netstat` 可见），脚本却报「代理未监听」。

根因：这两个 cmdlet 在权限受限环境直接抛 `拒绝访问`，
`-ErrorAction SilentlyContinue` 让它静默返回空，于是**把正在运行的服务判成没启动**。

修复：改用 `netstat -ano` 解析（普通用户权限即可），
封装成 `Test-PortListening` / `Test-LocalAddress`。
测试 `test_does_not_use_restricted_net_cmdlets` 禁止代码里再调用这两个 cmdlet。

#### 坑 3：`Test-Connection` 同样受限，且失败被当成「板子不在线」

修复：三态处理 —— `$null` = 探测不可用（只提示跳过检查）、
`$true`/`$false` = 真实结果。避免把「探测不了」误报成「板子离线」。

#### 坑 4：注释里的参数名与 param 块不一致

注释写 `-HostAddr 0.0.0.0`，param 里是 `$BindHost`。
PowerShell 对未知参数的处理会让传参静默失效，热点检查分支因此被跳过。

修复：统一为 `-BindHost`。测试 `test_doc_usage_matches_declared_params`
与 `test_bat_uses_declared_params` 检查注释与 `.bat` 里的参数名都在 param 块里。

> 三个测试都做过「故意改坏 → 确认测试失败 → 还原」的反向验证，不是空转。

### 坑 5（交付后暴露）：`.bat` 含中文 → cmd 按 GBK 读 UTF-8，命令被截断

第一版 `一键启动.bat` 里写了中文注释和中文提示。双击后报：

```
'e' 不是内部或外部命令，也不是可运行的程序或批处理文件。
'rt_all.ps1" -BindHost 0.0.0.0' 不是内部或外部命令...
'闈㈢殑閿欒淇℃伅銆?' 不是内部或外部命令...
```

即 `-File scripts\start_all.ps1` 被从中间劈成了 `e` 和 `rt_all.ps1`。

**根因**：Windows cmd 按 **OEM 代码页**（中文系统是 GBK/936）读取 `.bat`，
而文件是 UTF-8。UTF-8 的中文首字节（如 `0xE4`）在 GBK 下会被当成「前导字节」，
它会把**紧随其后的字节（可能正是换行符 `\r`/`\n`）当作尾字节吃掉**——
于是换行消失、多行合并，命令行被截断。

**为什么加 BOM 也不行**：cmd 会把 BOM 的三个字节当作第一条命令的一部分，
同样报错。这和 `.ps1` 的情况正好相反（`.ps1` **必须**有 BOM）。

**修复**：`.bat` 改为**纯 ASCII**，中文提示全部放在 `start_all.ps1` 里
（它是 UTF-8 with BOM，PowerShell 能正确解码）。

验证方式：用 `cmd /c "一键启动.bat"` 实跑，中文提示正常显示、命令完整执行。

新增 4 个测试锁住：

| 测试 | 作用 |
|---|---|
| `test_bat_is_pure_ascii` | `.bat` 不得含任何非 ASCII 字节 |
| `test_bat_has_no_utf8_bom` | `.bat` 不得带 BOM |
| `test_other_bats_are_pure_ascii` | `启动演示.bat` / `开始对话.bat` 同样检查 |
| `test_bat_uses_crlf_or_lf_consistently` | 换行符不得混用 |

> 已做反向验证：把中文写回 `.bat` 后 `test_bat_is_pure_ascii` 立即失败。

## 五、第 1~9 项逐项说明

### 1. 板子多轮上下文（最严重）

`_run_pipeline` 里每轮 `ConversationSession(self.card, self.llm)` 新建，
而该对象持有对话历史 —— 每轮新建等于「每轮都是全新对话」。

终端（`tools/dialogue_loop.py`）和网页 demo 都是长会话，**只有 WS 链路漏了**。
日志里 17 轮 LLM 调用全是 `*-t1`，即每轮都是该 session 的第 1 轮，是同一问题的旁证。

修复：会话挂到 `ClientSession.dialogue` 上，由 `_dialogue_for()` 懒创建并复用；
断开时在 `_cleanup()` 里释放。

**端到端验证**（真实 WebSocket + 真实协议编解码，模型/TTS 用替身）：

```
第 1 轮: 2 条  ['system', 'user']
第 2 轮: 4 条  ['system', 'user', 'assistant', 'user']
```

修复前第 2 轮仍是 2 条。已用「改回旧写法 → 测试失败」验证测试确实能抓回归。

### 2. 播放看门狗

`_run_pipeline` 发完音频就返回，`TURN_TIMEOUT_S` 的 `asyncio.timeout` 随之失效。
板子不回 `playback_done` 时状态永久停在 `PLAYING`，后续所有 `recording_start` 被判 `turn_busy`。

修复：进入 `PLAYING` 时挂看门狗，`max(音频时长 + 15s, 20s)` 内没收到
`playback_done` 就强制回 `IDLE` 并下发 `turn_done{reason: playback_timeout}`。
看门狗只在「仍是同一轮且仍在 PLAYING」时触发，不会误杀新一轮。

### 3. 上行声道降混

`VOICE_CHANNELS = (MIC1=1, MIC2=3, UNKNOWN=2)` 是按 4 通道 `RMNM` 写的。
固件实际发 **2 通道**（`voice_client.c: MIC_CHANNELS 2`），
`[c for c in VOICE_CHANNELS if c < 2]` 只剩 `[1]` —— **第二支麦克风被整体丢弃**。

修复：新增 `voice_channel_indices(channels)`，2 通道时两路都参与；
4 通道时按 `RMNM` 跳过 0 号回采。

> ⚠️ 这一项**未在真实硬件上复测**：本次环境没有板子。
> 单测覆盖了「两路都参与 / 回采被排除」，实际识别质量改善需上板确认。

### 4~5. 依赖与配置模板

`requirements.txt` 此前只列 4 个包，但 WS 服务真正 import 的
`websockets`、`numpy` 都没写。`.env.example` 缺全部 7 个 TTS 键、
`DEFAULT_CHARACTER_ID=default`（现用 elysia）、`LLM_MAX_TOKENS=256`（已降 128）。

修复后新增 `tests/test_config_artifacts.py`（21 个用例）锁定：
真正 import 的包必须在清单里、TTS 键必须齐全、模板不得含真实密钥、编码无 BOM。

### 6. 心跳与连接上限

`HEARTBEAT_TIMEOUT_S = 30.0` 与 `max_connections = 4` 定义后**从未被引用**，

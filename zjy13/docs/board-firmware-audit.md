# 板子与现有固件不足审查

日期：2026-10-28。方法：读取完整 Flash 备份、核对启动日志、通过 COM7 连续查询 3 次 STATUS。不刷写、不擦除、不执行校准。

## 结论

未发现足以判定板子损坏的证据。当前主要不足是固件的联网、可复现构建、性能诊断和更新机制；音频、电池等硬件能力尚未验收。不能将固件功能缺失等同于硬件故障。

## 已确认的问题与限制

1. **联网未成功**：启动日志与本次实时日志均出现 `reason 201 (NO_AP_FOUND)`。可能原因：SSID 不存在、5GHz 专用、信号弱、NVS 中凭据过期。需实际连接测试，**不能据此断定 Wi-Fi 芯片损坏**。
2. **渲染存在慢帧记录**：`late_frames=469 / frames=523`、`peak_render_us=134293`。缺少对应源码解释计数口径，**不能直接换算成 88.9% 丢帧率**。当前 idle 状态 `playing=false`、`frame_index=35`，多次查询不增长属静止正常，不能说动画一直在跑。
3. **构建版本为 `e8aa327-dirty`**：构建时工作区不干净。Flash 备份保留二进制，但**不含源码、ELF、sdkconfig**。没有这些，无法精确复现，也无法可靠调试。
4. **无标准双槽 OTA 布局**：分区表有 `factory` + `otadata`，但**没有 `ota_0`/`ota_1`**。这意味着不支持常规 A/B OTA 与自动回滚。是否存在定制升级路径未知。
5. **语音链路未被证实**：启动日志中**没有任何麦克风录音、音频上传或扬声器播放的证据**。但这只是"未观察到"，不等于代码里一定没有（相关初始化可能在别处或未打印日志）。
6. **`heap=6.62MB` 不是"内部 RAM 充足"的证据**：该数值是**含 PSRAM 的合计堆**。语音场景真正要看的是内部 SRAM、最大连续块、DMA 可用内存。当前报告缺这些数据。
7. **应用分区余量偏紧**：factory 分区 9 MB，镜像已占 7.32 MB（81%）。若新固件加入语音栈、LVGL 资源，容易溢出。

## 板子的客观限制

- ESP32-S3 适合采集、播放、显示和联网，不承担本项目的大型 ASR/LLM/TTS 推理。
- 8 MB PSRAM 与内部 SRAM 性质不同；显示帧缓冲、音频缓冲和 Wi-Fi 会竞争资源。
- Wi-Fi 为 2.4GHz，需要真实网络下验证延迟、断连恢复与吞吐。
- 内置麦克风与扬声器距离近，存在回采/啸叫风险；双麦及相关芯片并不意味着回声消除自动生效。第一版宜半双工。

## 必须更正旧报告的结论

- model 分区实际是 0x920000，大小 0x50c000，结束于 0xe2c000；不是 0x092000。
- 旧报告通过统计非 0xFF 字节得出的 99.1% / 99.6% 使用率是错的。实测 model 分区 0xFF 占 72.1%、0x00 占 6.7%，两者合计 78.9%，即该分区大部分是空区。旧统计把"非 0xFF"当成"已使用"，实际把随机数据误判为占用。
- 应用镜像实际占用：最后一个段结束于 0x772c98，即约 7.32 MB / 9.00 MB（81%），不是 99.1%。仍有约 1.7 MB 余量，但确实偏紧，后续加功能需注意。
- model 分区开头 64 字节为压缩数据特征（含 0x2b8a 等 LZ 类标记），不是明文文件系统索引。分区标签 "model" 与 SPIFFS 类型不构成"内含机器学习模型"的证据。
- model 标签和 SPIFFS 类型不能证明分区里有机器学习模型，需解析内容。
- 自检输出有 24 条 PASS 和 1 条数值诊断、0 条 FAIL，不是 25 个测试失败了一个，也不能证明所有物理传感器/显示/触摸都完成验收。
- 备份为完整 16777216 字节 Flash，SHA256 为 4cf96ed593c6b036342a0854af4f66fbf91e55f6f372adf163e37a68db457908。只对前 1 MiB 做过第二次读取比对，不能宣称全部 16 MiB 二次验证；尚未做实际恢复试验，也未备份 eFuse。

## 优先级建议

P0：保留第二份离线 Flash 副本与哈希，备份可能含 Wi-Fi 凭据，不应上传公开仓库；取得对应 ai_pet_badge 源码、ELF、sdkconfig 和资源清单。

P1：实际连上 2.4GHz Wi-Fi；测双麦各通道、扬声器和采样率；确认 DMA/内部堆余量。未验收前不替换现有固件。

P2：定位慢帧耗时（读取/解码/旋转/绘制/刷屏），把网络与音频处理放到不会长时间阻塞 UI 的任务中；规划 OTA 双槽或明确采用 USB 更新。

尚未验收：麦克风音质、扬声器、回声处理、电池容量/充放电/保护、蓝牙、长时间稳定性、真实 Wi-Fi 音频传输。当前没有证据表明必须更换开发板。

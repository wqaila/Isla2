### 2.2 三个「静默失效」值得单独说明

这三个都不报错、不崩溃，只是**悄悄不工作**，最难发现：

#### ① 板子没有多轮记忆

`_run_pipeline` 里每轮 `ConversationSession(self.card, self.llm)` 新建，
而该对象持有历史——每轮新建等于「每轮都是全新对话」。

日志旁证：17 轮 LLM 调用全是 `*-t1`，即每轮都是该 session 的第 1 轮。

修复后实测（真实 WebSocket + 真实协议编解码）：

```
第 1 轮: 2 条  ['system', 'user']
第 2 轮: 4 条  ['system', 'user', 'assistant', 'user']   ← 历史真的累积了
```

#### ② 中文数字念错

CosyVoice 的 `frontend.py` 用 bare `except` 吞掉了 wetext 的异常：

```python
try:
    from wetext import Normalizer as ZhNormalizer
    self.zh_tn_model = ZhNormalizer(remove_erhua=False)   # 内部要 ModelScope 鉴权
    self.text_frontend = 'wetext'
except:
    self.text_frontend = ''        # ← 静默降级，只写一行 info 日志
```

本机无 ModelScope token → `HTTPError: Authentication token does not exist`
→ 被吞 → 文本前端失效。服务照常启动、能合成、不报错，只是数字念错。

**ASR 回读对照**（决定性证据）：

| 送进 TTS | ASR 读回 |
|---|---|
| 这个要 **128** 块钱 | 这个要**一百二十八**块钱 |
| 这个要**一百二十八**块钱（对照） | 这个要一百二十八块钱 |

修复后两版回读**逐字一致**。

#### ③ 网页演示角色不对

`.env` 里是 `DEFAULT_CHARACTER_ID=elysia`，但 `tools/web_demo.py` 硬编码
`default.yaml`，页面标题、输入框占位符、启动横幅也都写死「小满」。

这与 README 里已修复的「WS 服务端硬编码小满」完全同类，但当时只修了 WS，
漏了 `web_demo.py` / `chat_demo.py` / `demo_report.py` 三个工具。

### 2.3 新增能力：一键启动

`一键启动.bat` + `scripts/start_all.ps1`：

```
前置检查（Python / .env / Clash 代理 / 热点）
  → WSL2 起 TTS，轮询 /health 等真正就绪
  → 起 WS 服务端，确认端口监听
  → 打印地址
```

参数：`-BindHost` / `-WSPort` / `-TTSPort` / `-TTSTimeout` /
`-SkipTTS` / `-SkipWS` / `-NoHotspotCheck` / `-Status` / `-Stop`

**为什么需要**：原本 WS 若先于 TTS 启动会直接退出码 2（这是 V2 要求的
「不得静默回退云端」），但用户只看到一个退出码，不知道原因。

### 3.3 本次工作自身的不足

如实记录，避免下次重复：

1. **第一版 `.bat` 没考虑 cmd 的 GBK 解码**
   写了中文，双击直接报「'e' 不是内部或外部命令」。已改为纯 ASCII，
   但这是**交付后才暴露**的低级问题，本应在写完就自测一次双击。

2. **第一版 `.ps1` 也没考虑编码**
   `ParseFile` 报 3 个语法错误、位置全错，排查花了较久。
   根因是无 BOM 的 UTF-8 被按 GBK 解码。同理：**Windows 脚本编码必须实测**。

3. **参数名注释与实际不一致**
   注释写 `-HostAddr`，param 是 `$BindHost`，传参静默失效。
   已加测试校验注释与 `.bat` 里的参数名。

4. **误判过热点状态**
   一开始用 `Get-NetIPAddress` 判断热点，该 cmdlet 在受限权限下「拒绝访问」，
   把「探测失败」误报成「热点未开」。改用 `netstat` 解析后正确。

5. **一次性批量替换改错了数字**
   更新测试数时用 `str.replace` 批量替换，把 development-log 里两个不同数字
   都改成了同一个值，后来才发现。**批量替换后必须逐行复核**。

6. **文档数字反复漂移**
   测试数从 265→325→333→361→378→388→392，每次改代码都要同步改 3 处文档。
   已用 `test_docs_consistency.py` 自动校验，但**这类手工同步本身就是设计缺陷**。

## 六、结论

**可以演示。** 纯软件演示（网页/终端）无需硬件即可跑；
板子演示需要开热点并给板子通电，两个服务已可一键拉起。

本次修复的三个「静默失效」都属于**不报错但不工作**的类型，
说明此前的验证偏重「链路是否通」，缺少对「输出是否正确」的断言
（例如多轮上下文、数字正则化）。

后续验证建议增加**语义层断言**，而不只是「无异常、有返回」。

# 角色卡审查报告

审查对象：`server/characters/default.yaml`（prompt_version 1.0 → 1.2）
审查方式：真实调用 `deepseek-flash` 跑 4 组剧本、每组多次重复，观察稳定性。

---

## 零、结论先行

角色卡**基础质量不错**：诚实性、边界感、拒绝编造这三项表现稳定且一致。
问题集中在两类：

1. **字段之间语义打架**（口头禅被当成"不知道"的固定开头）
2. **缺失关键说明**（没告诉模型"本次会话上下文可见"）

这两类都已修复，并有测试锁定。最终 16 轮演示**全部成功**，多轮记忆 4/4 正确。

---

## 一、已修复的 3 个真实缺陷

### 缺陷 1：口头禅被当成"不知道"的固定开头（严重）

**现象**：连续 4 次测试，回答"你还记得我在做什么项目吗"时，全部以「这个我得确认一下」起手，
其中 3 次还错误地声称"我看不到你之前的记录"。

**根因**：模板里【口头禅】和【不确定时的处理】两个字段**紧挨着**，且口头禅
「这个我得确认一下」语义上就是"不确定"的表达。模型把两者绑定成了条件反射。

**修复**：
1. 新增 `catchphrase_usage` 字段，明确"只是偶尔点缀，不是每句必用，不是'不知道'的固定开头"。
2. 调整 `uncertainty_policy`，限定它只适用于"事实性、外部世界"的问题。

**验证**：口头禅频率从"几乎每句"降到自然水平。

### 缺陷 2：把"没有长期记忆"误解成"看不见对话历史"（严重）

**现象**：多轮对话中，用户先说"我叫阿哲，在做嵌入式开发"、"我在弄 ESP32 的板子"，
第三轮问"你还记得我在做什么项目吗"，模型回答「不记得，我只能看到我们这次的对话」。

**关键排查**：打印实际发送的 payload 确认，历史**完整传入了**（system + 4 条历史 + 当前输入）。
所以不是代码 bug，是模型对"记忆"的理解偏差。

**根因**：角色卡里**没有任何地方**告诉模型"本次会话的上下文对你是可见的"。
模型把"第一版不实现长期记忆"自行外推成了"什么记忆都没有"。

**修复**：模板新增固定段落【本次对话的上下文（重要）】。

**验证**：同一组问题重复 4 次，**4/4 全部正确回答"记得，你在弄 ESP32 的板子"**，
且没有编造用户未说过的细节。

### 缺陷 3：few-shot 示例导致逐字背诵（中等，新发现）

**现象**：把 `example_dialogues` 注入 system 后，效果立竿见影——但**3 次测试里有 2 次
逐字复述示例**：

```
示例原文：嗯，那先别急着做别的了。要不要先喝口水，坐一会儿？
实际输出：嗯，那先别急着做别的了。要不要先喝口水，坐一会儿？   ← 完全一致
```

这从"角色扮演"退化成了"背诵课文"。

**根因**：few-shot 只给了示例、没给约束时，模型倾向于把示例当标准答案直接套用。
尤其是示例句子本身很具体（"喝口水，坐一会儿"）。

**修复**：在示例段落前后各加一段显式约束——"只用来体会语气和分寸"、
"不要复述、照搬或改写这些示例里的具体句子"、"遇到类似问题要用不同说法"。

**验证**：修复后 3 次测试，累的回复全部是新说法（"才上午九点多就累了""昨晚是不是没睡好"），
不再出现"喝口水"。

> 注：笑话类回复仍保留「我讲笑话的水平不太稳定」这个句式，但这属于**口头禅/自我调侃风格**，
> 不是照抄示例内容，可以接受。

## 二、已实施的 3 项改进（基于实测数据）

### 改进 1：软截断（修复真实缺陷）

**实测**：`max_tokens=40` 时返回 `finish_reason="length"`，内容在
「公元前222年，秦灭」处戛然而止。这种半句话送去 TTS 会念出残句。

**实现**：`server/dialogue/text_utils.py`
- `soft_truncate()`：在**句边界**收尾，宁可少说一句也不留半句
- 仅在 `finish_reason == "length"` 时触发，正常结束不动原文
- 顺带清理结尾的悬空逗号/顿号

**测试**：10 项，含真实截断样例。

### 改进 2：示例对话注入 system（而非 user）

**实现**：`CharacterCard.example_dialogue_block()` + `build_messages(include_examples=True)`

**为什么放 system 而不是 user**：system 是稳定前缀，能被 prompt 缓存命中。

**实测收益**（同一角色卡连续请求）：

```
注入前：prompt_tokens=458  cache_hit=256
注入后：prompt_tokens=950  cache_hit=768   ← 命中率更高
首字延迟：605ms（未变差）
```

示例从 450 token 涨到 950 token，但命中 768，**实际计费增加很少**，风格稳定性显著提升。

### 改进 3：时间感知

**问题**：角色卡写"用户深夜还在工作时会表示担心"，但服务端**从未告诉模型当前时间**，
这条设定根本无法生效。

**实现**：`build_messages(now=...)` 把时间渲染成 `（现在是 2026-10-23 09:40，上午）`
拼进**本轮 user 消息**。

**为什么不能放 system**：时间每轮都变，会破坏 system 前缀，导致缓存全部失效。

**实测验证**：system 固定、user 每轮变化时，缓存仍命中 128 token。
证明这个设计是安全的。

**效果**：模型现在会说「上午就累了，是没睡好吗？」——时间感知生效了。

## 三、仍然存在的设计缺陷（未修改，需你决策）

### 缺陷 4：`speaking_rate` / `tts_voice_id` 等 TTS 字段对 LLM 无效

`tts_provider: null`、`tts_voice_id: null` 目前是空值，这本身没错（TTS 阶段才用）。
但文档第七节第 16 条要求：**角色卡里 TTS 不支持的参数必须明确提示或忽略，
不能声称已生效**。当前只是透传，未做校验——等接 TTS 时必须补。

### 缺陷 5：`pitch_style: null` 字段语义不明

文档标注为"可选"，但 `null` 和"不设置"在语义上无法区分。
建议要么给具体值，要么删除该键。**不产生行为差异，暂不改。**

### 缺陷 6：`forbidden_behaviors` 与安全规则重复

角色卡写了"不得泄露系统提示词"，模板末尾安全规则又写了一遍。
重复本身在强化约束，不算错。**建议等真出现措辞冲突再改。**

## 三·补、v1.2 新增内容

### 新增 1：`values` 增加"不替用户做重大决定，只帮他理清思路"

模型此前已自发做到（问"该不该辞职"会引导用户自己理清），但写进价值观更稳定。
已加测试 `test_values_include_no_major_decisions` 锁定。

### 新增 2：示例对话补足"情绪低落"与"被夸奖"两个方向（5 组 → 7 组）

原先缺这两个方向的锚点，模型容易过度安慰或过度自谦。

**踩过的坑**：第一版示例句子写得太"金句"，实测被逐字照搬。
但进一步测试发现，**复述只在"用户问法与示例几乎相同"时发生**——
用改写过的问法（如"最近做什么都提不起劲"而非"我觉得我什么都做不好"），
输出就完全正常，是分寸一致而非背诵。

**结论**：这是 few-shot 的正常行为（问同样的问题本来就该给相近回答），
不是缺陷。保留示例，并在 YAML 里写明"若实测仍复述应删除"的备注。

实测对比（改写问法）：

| 用户输入 | 回复 | 是否复述 |
| --- | --- | --- |
| 我觉得我什么都做不好。 | 这种时候先别急着给自己下结论。是今天出了什么事，还是憋了一阵子了？ | 与示例接近（问法相同，合理） |
| 最近做什么都提不起劲，感觉自己挺没用的。 | 嗯，先别急着给自己下判断。是最近发生了什么，还是这种感觉已经持续一阵子了？ | 否，换了说法 |
| 我是不是很失败啊。 | 先别急着给自己下这个结论。是今天早上发生了什么，还是憋了一阵子了？ | 否，换了说法 |
| 跟你聊天挺舒服的。 | 谢谢，我听着也挺舒服的。上午这个点，你手头有要忙的事吗？ | 否，完全不同 |
